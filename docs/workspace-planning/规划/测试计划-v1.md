## 一、测试目标与「测过了」的定义

### 1.1 三份主张的合取口径

五份思考从三个不同起点收敛到同一结论：**「测过了」不是 eval 全绿，而是多层证据的合取**。本计划把三份主张合取为可执行的判定：

- **G1 的三层合取**：契约层（规划 §1.2 六条验收句各有断言咬住）× 泛化层（开发者没见过的语料/agent/改形上指标不塌方）× 诚实层（计量仪器被校准、覆盖边界如实披露——「不骗人」本身是可测对象）。
- **M1 的三段定义**：测过 = 上游实收 bytes 级零原值 + 用户可见零残留（**形状检测器 ∪ 映射 digest 反查 oracle 的并集口径**）+ 用户环境零改动；性能只对「直通 vs 经壳」的差值负责。
- **M3 的用例级判据**：一条用例算不算数，看它失败时能不能指认一个**用户会遭遇的具体伤害**——指认不出来的是覆盖率幻觉。本卷第三节每组用例表均含「失败时指认的用户伤害」列，此列不可为空。

**合并后的判定：「测过了」≡ 以下五条同时成立**：

| # | 层 | 判定内容 | 主要出处 |
|---|---|---|---|
| 1 | 契约 | 规划 §1.2 六条验收句（脱敏/还原/无感/商业 agent 有效/不骗人/审计红线）每条至少一条断言咬住，且断言失败可指认用户伤害 | G1§一、M3§0.1 |
| 2 | 仪器 | 一切泄漏/残留/存活数字出自 T0 校准后的**并集口径**仪器；T0 未全绿前，该类数字一律标注「无效计量」，不得进任何阶段门 | M2§0.3（实测 7 坏形态 5 假绿）、M1§4.1（互补盲区） |
| 3 | 泛化 | holdout 五面（真实语料/未见 agent/对抗改写/长上下文/多轮漂移）在里程碑门执行并达标，或如实 DEFERRED（无授权语料不得合成冒充） | G1§二、G2§二、M3§2 |
| 4 | 诚实 | 覆盖披露、泄漏计数、已知缺口：面板数 = 审计数、可复算；未覆盖出口有负控（走代理计数必须增长） | G1§一a、M1§一a、M3§1a |
| 5 | 环境 | 安装前后系统快照一致（证书库/env/信任库零污染）、卸载一键可撤销复验 | M1§一a、规划 §四M5 |

### 1.2 三条硬不变量（一票否决）与质量线（披露/升级）

**硬不变量**（失败 = 该阶段门不通过，无豁免）：

1. **上游实收 bytes 级零原值**——含敏感实体与**本地网关 key**（key 也是不该出网的敏感信息，G2§一a-1）。
2. **错还原率 = 0**——所有查表未命中、所有幻觉/扩写形态、所有跨实例旧占位符，一律原样放行，**宁残留、不错还**（G1§四.2 提出、M3§4.3 升格一等验收；与残留率质量线分开断言分开处置）。
3. **审计库与壳日志零明文**——基线 §2.5 红线原样继承（库文件 bytes 级扫描 0/7 原值命中口径）。映射库（session_map）M3 前含归一化原值是**登记在案的设计事实与已知缺口**（基线 §六#6），按 V7-01/V7-03 单独处置，不与本红线混同。

**质量线**（失败 → 披露 + 按约定升级，不一票否决）：

- 占位符残留率 ≤ 2%（按占位符计，并集口径，E2 定标后 owner 可调；规划 §1.2-#2）；
- 可救形态存活率 ≥ 95%（E2 杀死线：< 95% → 占位符机制整体重审升级 owner，规划 §四E2）；
- TTFT 增量 p50 ≤ 20ms / p95 ≤ 50ms @ ≤20KB 请求（三档门执行，见 T4）。

### 1.3 开发者可见 vs holdout 的分层判据

三份思考给出三句同义判据（G1「字面被看见是否存在应试激励」/ G2「通过用例的最短路径是否严格窄于满足验收句的行为」/ M1「读过之后还能不能区分实现了与迎合了」），合取操作化为：

- **可见**（本卷）：契约/机制断言（键语义、头注入、协议形状、转发保真）、全部负例（误替/误还原/pinning 不绕过/静默拦截禁令）、**仪器校准集本身**（仪器有盲区是必须让开发者知道的结构性事实，M1§二）。
- **holdout**（保密卷）：真实语料分布、对抗改写实例与采样配方、未见 agent 名单与生成器种子、多轮漂移构造配方、长上下文密度/位置参数。
- **一句话**：**仪器公开、考卷保密**（G2§二）。统计指标的口径、分母、杀死线全部公开（本卷与 holdout 卷 §三一致），喂给指标的具体语料保密。

### 1.4 两条全局禁令

- **单机单次毫秒数禁作阈值**：19ms/20KB、2ms/2000 字、0.26ms/50 占位符等均为单机单次实测佐证（基线 §三表 B 注），不得写进 thresholds 当门（M3§5.1）。
- **pytest 不作门**：基线实测 `python -m pytest evals/m0_infra` 为空跑（exit 4 / collected 0，基线 §五#7）；判定一律以 `python wf_run.py venv -m evals.<模块>` 的 exit code 为准（基线 §八#2、M2§3、M3§3）。

## 三、各组详细设计

### T0 泄漏检测仪器自测与校准（最高优先）

**目的**：先测尺子再测产品。M2 实测（§0.3）：现状泄漏断言（`ops/e2e_smoke.py:1348-1349` 调 `tolerant_placeholder_hits`）对 7 个真实坏形态 **5 个判 PASS（假绿）**——「残留率在两个补丁落地前不是测量，是恒零」。M1 实测（§四）证明形状检测器与映射 digest 反查 oracle **互补盲区**：16-hex 扩展/括号剥除/裸 hex/表格拆分只有 oracle 抓到，digest 改写幻觉只有形状检测器抓到。本组是 M0 步骤 1 两个 mapper 补丁（标签副索引、裸 digest 检测面，规划 §三g）的**验收本体**，也是本计划一切泄漏/残留/存活断言的前置门。

**前置**：M0 步骤 0 冻结提交完成（git status 归零）；本组用例**先于补丁写入并先红**（红/绿夹具纪律：补丁前 FAIL、补丁后 PASS，G1§六 P0-②）。

### T1 契约断言群（接入层 × 键域 × 协议面）

**目的**：把规划 §1.2 的可判定验收句与三 a/b/f 裁决倒推成三维断言群（G2§一方法）。每一维都有独立的失败路径：接入层错 = 流量到不了/环境被改；键域错 = 占位符漂移或错还原；协议面错 = 还原失效直打用户脸。

**前置**：T0 全绿（一切「零残留」期望都是并集口径）；壳与实例标识已实现（M1 竖切）。

**A. 接入层（文件：t1_shell.py）**

| 用例id | 输入 | 步骤 | 期望 | 失败时指认的用户伤害 |
|---|---|---|---|---|
| V1-01 | 壳监听配置 | 从非回环接口发起连接；扫描监听地址 | 非回环不可达；只听 127.0.0.1/::1 | 工具变成局域网攻击面——他人经你的壳出网、读映射（规划 R10） |
| V1-02 | 连续 N（≥10）个请求经壳 | 抓每个请求的会话头值逐字节比对 | `x-anongw-session-id` 恒等于安装实例标识；**反例断言**：若壳退化为每请求现造会话（`gateway/app.py:385-389` 行为）必红——同值占位符逐轮漂移（M1 实测：稳定会话 STABLE、现造 BROKEN） | 多轮对话中同一个人变成多个占位符 → 模型上下文断裂、还原失败打在用户脸上 |

### T4 性能预算组

**目的**：「无感」在测试里唯一可操作的定义是**差值**，不是绝对值（M1§一e）。预算：TTFT 增量 p50 ≤ 20ms / p95 ≤ 50ms @ ≤20KB（规划 §三e）；大上下文 p95 ≤ 100ms @ 50k（E5 修复后）；NER 段硬预算 30ms 超限降级（M4）。

**前置**：T1 最小回路；E4 harness（一次性骨架代理）即本组量尺，**一次做对**——M0 的 E4 与 M1-#4/M2-#3/M5 终验共用同一测量代码（G1§五）。

**三档门框架**（M3§5.2 核心主张，吸收 G1§五.4 双门与 M2§5.3 WARN 带）：

| 档 | 何时跑 | 断言什么 | 防抖机制 |
|---|---|---|---|
| 功能门 | 每次提交 | 只测「20KB 请求被正确处理、输出正确」——**无时间断言** | 时间断言进功能门 = 制造 flaky = 教人忽略红灯 |
| 基准门 | 每日/手动，专用机不并行 | 报完整分布（p50/p95/p99/max + 机器状态）；断言相对回归比 `p95 ≤ 基线p95 × 1.5` 且 `基线p95 ≤ 0.5 × 预算`（防测量代码本身坏了） | CI 内可加 2× 预算宽门（p95 ≤ 100ms@20KB）WARN 带（HARD 50/ADVISORY 80 分级）+ 有条件重试（重跑仍超才 FAIL，日志必写「首跑 X / 重跑 Y」） |
| 预算门 | 发版前一次性 | n ≥ 200 对照规划 §三e 严格判 | **不过就记录，不重跑到过**（重跑到过 = 掩盖问题） |

## 四、CI 与执行顺序

### 4.1 四条排序原则

1. **先仪器后功能**：T0 是一切泄漏/残留/存活断言的前置门（M2§0.3：5/7 假绿；M1§4.1：仪器与被测物同源盲区不可能被仪器自己发现）。T0 未全绿期间，CI 可跑功能组但一切泄漏类期望标注「无效计量」，阶段门不予采信。
2. **先证伪后建造**：E1–E5 的 harness 是可重复 eval（证伪实验的测试化，G1§六 P0-①）——E2 天花板 harness 与长期回归门共用同一测量代码；杀死线（存活 < 95% → 机制重审）做进门线而非报告注脚。
3. **先安全网后重构**：V5-01（OpenAI A/B 安全网）在 M2 适配器重构动工前就位；V2-02（端口基床）在一切起端口的组之前。
4. **先基床后套件**：`_harness/_portalloc/_mangles/thresholds` 四件先行（M2§6.2 P0 清单），否则套件继承分叉与假红。

### 4.2 每提交 CI（开发者可见范围）

T0 + T1 + T2（规划点名模块集）+ T3 的 V3-01/05/06/08 + T5 已实装协议面 + T7；性能只跑功能门（无时间断言）+ 可选 WARN 宽门。判定一律 exit code；PRECOND-FAIL（端口/环境）与 FAIL 严格区分，前者不红构建但登记。

### 4.3 阶段门

| 阶段 | 门内容 |
|---|---|
| M0 | 冻结销项（git status 归零）；T0 全绿（= 两补丁验收）；V2-02/05/06 基床就位；V8-01 夹具 SKIP 态在位；E1–E5 各出一页结论（含杀死判定）；owner 拿到 F1/F4 答复 |
| M1 | V1-01–06/08–13、V3-01–03/05、V7-01、V4-01 首批数字（E4 完整版）；引擎三模块零回归；holdout 第一版已写（V6-01 可执行） |
| M2 | T5 全量（V5-01–10）；矩阵 ≥ 2 agent 端到端（V3-02–04/06/07）；V4-04 大上下文达标；注入增益实测（逐 agent 有/无对照，据测定开关默认值——仅优化位）；m4 回归；**holdout M2 门首跑**（V6-01–03） |
| M3 | V1-08 跨重启档、V1-14、V7-02/03、V4-06 并发流式；m7 重跑 |
| M4 | T8 解 SKIP 全绿（E3 门前置） |
| M5 | T9 全量 + 预算门终验 + **holdout M5 门** + 自查清单勾销 |

### 4.4 DEFERRED/SKIP 语义

真实腿不可达（localhost:9004 不通）→ DEFERRED：不计失败、如实登记、可跑时补（基线 §七#6 的 SKIP 争议教训——「按指令未跑」不得写成「环境不具备」）；条件模块（V5-09、V8 组）→ 显式 SKIP + 原因一行。两者都不允许静默缺席。
