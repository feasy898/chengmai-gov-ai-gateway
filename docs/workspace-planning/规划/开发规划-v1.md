## 一、目标与范围

### 1.1 人类意图转译

人类原话要求：出一个网工具（规则过滤或快速小模型皆可），出网流量经过后敏感信息被替换为特定占位符；远端 LLM 回复后匹配占位符并还原回敏感信息，**用户全程无感**；并且**最好对用户使用的商业 agent 也有效**。

转译为工程语言，本题 = 把基线「客户端知情配合的显式 API 网关」（改 endpoint、带部门 key、传会话头、说 OpenAI 协议）改造为「客户端不知情的本机工具」。五份思考轨迹收敛出的差距不是引擎，而是：**入口（流量怎么到工具手里）、会话身份（没人传会话号时占位符一致性靠什么）、协议壳（非 OpenAI 形状的响应还原）、渗漏可见性（还原失败打在用户脸上）**。引擎侧识别/脱敏/还原/审计已经 16/16 模块三族实测全绿（基线 §三表 A）。

### 1.2 成功的验收级定义（可判定）

以下每条都是可判定的验收句，不是愿景：

1. **脱敏成立**：经工具出网的请求，上游实收 bytes 级零原值（沿用基线口径，基线 §表 B「上游实收原值 0 命中」三族冒烟实测的同款判定方法）。
2. **还原成立**：远端回复中的占位符被还原，用户最终看到的文本**占位符残留率 ≤ 2%（按占位符计，M2 实测定标后可由 owner 调整；目标 98% 还原成功）**。计量仪器为修补后的 `tolerant_placeholder_hits` 泄漏检测面（M1 交付，见三 g）。M2 实验的杀死线沿用 M2 轨迹标准：还原成功率 < 95% → 占位符机制整体重审升级 owner。
3. **无感成立**（量化定义见三 e）：请求侧 TTFT 增量 p50 ≤ 20ms / p95 ≤ 50ms（≤ 20KB 请求，规则全链）；流式还原不引入基线语义之外的额外用户可见缓冲；还原口径为**归一化等价**（基线 §2.2 口径节裁定，非逐字还原——含分隔符手机号还原为归一化形态；与 G1「逐字全等」表述冲突处以基线为准）。
4. **商业 agent 有效**：M2 适配矩阵中 ≥ 2 个真实商业 agent 端到端打通（本机已实证可配的 zcode / kimi 至少其一在 M1 即打通；矩阵全量清单由 owner 在 M0 前给定，见 5.2-F4）。每个 agent 的覆盖方式与边界在矩阵中如实登记。
5. **不骗人**：工具诚实报告自己的覆盖面——被处理的会话数、计量到的未还原泄漏数、以及（T2/T3 形态下）哪些出口路径未被覆盖（M1/M5 交付计数器与面板）。静默的部分覆盖是产品级风险（M1 轨迹 §2.2 结论，本规划采纳为一等原则）。
6. **审计红线继承**：审计库零明文红线原样继承（基线 §2.5：库文件 bytes 级扫描 0/7 原值命中，m7 17/17）；本机映射库的静态加密在 M3 交付（见 5.2-F5）。

### 1.3 明确不做什么（v1 范围外）

- **浏览器 SaaS agent（网页版聊天）**：无可配 endpoint、载荷为私有 JSON/websocket 形态，v1 不覆盖；插件形态留 v2 评估（G1 §2.4、M1 §3.4）。
- **绕过证书固定（pinning）**：绝不做。pinning 命中的 app 进排除名单、明示不覆盖（G1 §2.3 修正后立场，五轨迹无异议）。
- **透传形态下的政务云路由**：商业 agent 的凭据/计费/会话绑在其商业服务上，改发政务云上游不可表达（G1 拍板④、G2 §2.2、M3 §1 一致）。三路由只在网关自营形态（agent 直配我方 baseURL）保留（见三 f）。
- **移动端、多用户/多部门**：v1 是单用户本机工具；部门 key/属主绑定机制不在壳层使用。
- **NER 小模型进主链**：v1 不做，M4 条件立项（见三 c）。
- **自动补救重问**（还原失败时自动重发 LLM）：v1 只计量+提示，不做（无失败分布数据，M1 §2.4 自认；秒级重试违反无感预算）。
- **输出侧内容风控**：基线 NullModerator 占位现状维持（基线 §五#2），不在本工具范围。
- **文件通道/OCR**：基线已有且实测（m6 12/12+6/6），与本工具的出网流量主线无关，不纳入 v1 壳层。
- **真实渗透测试**：登记为缺口（基线 §六#19），M5 只做自查清单不做渗透。

## 三、核心架构决策

裁决总览：**a 回环显式为主 / b 值级键 / c 规则为主·模型只当识别器 / d v1=OpenAI、M2 加 Anthropic / e TTFT 增量 p50≤20ms·p95≤50ms**；附加裁决 f 透传形态功能退化、g 占位符形态不换、h 引擎双接法。

### a. 部署形态：回环显式代理为主，透明 MITM 为辅且押后

**决定**：按三层递进，v1 以前两层为主形态——

- **T1（M1，主）**：回环网关 + baseURL 直配。agent 的 endpoint 配置指向本机壳/网关（HTTP 明文听回环，无 TLS、无 CA、无 pinning 问题）。本机已实证：zcode 经 `provider.baseURL` 配置、kimi 经 `config.toml base_url` 配置（G1 引本机 AGENTS.md §七/§八）——**CLI 编码 agent 这一大类今天就能纯配置接入，零代码**。
- **T2（M2，辅）**：wrapper 启动器 + env 显式代理（HTTP_PROXY/HTTPS_PROXY）+ **按运行时** CA 分发（`REQUESTS_CA_BUNDLE`/`SSL_CERT_FILE`/`NODE_EXTRA_CA_CERTS` 等，G1 §2.2 清单），**v1 不写系统信任库**。注意：显式代理做内容级脱敏必然 MITM + 自建 CA（G1 自我修正①、G2 §2.2 同判）——显式与透明的真实差别只在流量怎么被引来与故障半径。
- **T3（M3 后按证据评估，非承诺）**：TUN/SNI 白名单透明 MITM，仅当 E1 证明存在「硬编码 endpoint 且不认 env 代理且不 pin」的必保 app，且 owner 拍板接受系统级 CA 时立项。域名白名单必须坚持（只对 LLM 域名 MITM），否则工具一挂全网断（G2 §2.2）。

**商业 agent 兼容性结论**：可配 endpoint 的 CLI 类（zcode/kimi 本机实证；Claude Code/Cursor BYO/Cline/Aider/Continue 类，M1/M3 轨迹列举，待 E1 实证）→ T1 即覆盖；认 env 代理的桌面/CLI app → T2；硬编码 endpoint 的封闭 app → T3 候补，pinning 命中即排除名单；SaaS 网页 agent → v1 不覆盖（1.3）。「对商业 agent 有效」的兑现率由 M2 适配矩阵如实计量并披露（1.2-#5）。

**被否选项**：透明 MITM 为主（否——首个障碍是行政的：政务终端装根 CA 很可能被策略禁止，M3 §2.2；且 pinning/QUIC/tailscale 共存三险，G1 §2.3；五轨迹信心排序全部把透明形态放在后位）；浏览器/IDE 插件为主（否——覆盖窄、与站点结构耦合脆，G1 §2.4、M1 §3.4，留 v2）。

### b. 会话身份：值级键（安装实例级）——采纳 M3 分叉的值级侧

**决定**：anongw-transparent 采用**值级（安装实例级）占位符键**：把一个**恒定的安装实例标识**喂进基线现有 digest 公式的 session 槽（`digest = HMAC(MASK_KEY, f"{instance_id}\x1f{type}\x1f{normalized}")`），映射表成为本机全局字典——同值在本机任何时候恒同占位符，回写层**完全不需要知道会话**，「会话路由」难题（M1 差异一、M2 §4.2）整体删除。每安装实例独立 key：换机器/重装 = 新的、不可关联的命名空间（M3 §1）。

**对基线 mapper.py 的改动面**（明确到可执行）：
- digest 公式与摘要机制**零改动**——值级语义经「壳层恒定注入实例会话号」达成（见 h 接法），`mapper.py:222-224` 一行不动；
- mapper 上唯二改动是 M0 的还原鲁棒性补丁（标签副索引 + 裸 digest 检测面，见三 g），属缺陷修复不属键改造；
- 生命周期改动在壳/存储层：映射持久化、保留策略、静态加密（M3），不动 mapper 摘要机制；
- 基线网关自身的会话级语义**原样保留**（显式传头的客户端行为不变），两形态并存互不污染。基线 m3「跨会话互异」断言继续在网关形态成立；新工具自有断言相反（跨会话/跨进程/跨重启同值恒同），写入新 eval。

**理由**：单用户本机工具中，会话级抗链接属性防的是跨部门链接（基线设计意图，`mapper.py:9-10` docstring），该威胁面在单用户形态不存在（G1 §4.3）；值级键对会话漂移（历史压缩、指纹漂移）结构性免疫。

**被否选项**：会话级 + 对话指纹推断（M1 方案：首条 user 消息 sha256 前 12 位，进程内多轮实测稳定、形态合规——否因：历史被压缩时前缀指纹漂移属结构性风险（M3，推断未实测但成理），且为已可删除的问题保留一套推断机不值）；连接级会话（M2 自己否掉：keep-alive 上几十轮不同话题会跨题污染）；直接改 mapper 公式去会话化（否——不必要且动摇已验收基线）。

**遗留**：本机内跨会话可关联是隐私属性让步，登记 owner 确认（5.2-F2，推荐接受）。

### c. 判定层：规则为主；快速小模型只当「识别器」，且 v1 不进主链

**决定**：
- 规则层为主判定：结构化实体上规则+校验位是支配性方案（召回 1.0000/618、≈2ms、可解释、零模型依赖），任何模型的边际增量为零（G1 §三、G2 §2.1、M2 §2.1 三方同判）。规则全链实测 19ms/20KB 完整 agent 请求（M1），预算内。
- 「JEV 式快速小模型」的**正确接入位是 span 级 NER 识别器**（补人名/住址/机构名等开放词表——恰是基线 NER 恒空、39.8% 实体不可检出的洞），**绝不是请求级二值判别器**（粒度错误，判别完还得抽取，时延与错误率双输，G2 §2.1(a)/(b)），**更不进处置决策**——路由/拦截/脱敏定性保持规则可解释（G1「识别器不当路由器」；政务处置须可审计可申诉）。
- 级联触发条件 = 规则层未命中且文本像自然语言，不是每次都过模型（M2 §2.2）；「快」来自分片与并行合并，不来自把模型塞进主链（M1 §2.1、G2 修正⑤）。
- **v1 不做 NER，M4 条件立项**，前置门：M0-E3 真实语料开放词表占比量化 + owner 语料授权 + 模型可得（本机 CPU 可跑量级，量化后 <100M 参数——G2 估算）。立项后先影子模式（异步跑、只记「本该拦什么」、反哺词表，证明 precision/recall 净胜后再进主链管窄触发面，M1 §2.1）；进主链须带：30ms 硬时间预算超限即降级回规则（绝不阻塞主链，继承 `judge.py:10-11` 词表降级纪律，M3 §2.4）、重叠 span 仲裁规则（`mapper.py:262` 现为 start 降序逐个切片，两层产重叠 span 时拼接直接坏，且语义层今日故意无 span——`recognizers/semantic/adapter.py:110-114`——换有 span 的模型是契约变更，M3 §2.1 层③）、白名单在 NER 层复刻（基线 0/22 的面）。**必须本机推理**：NER 输入即原文，走云 API/tunnel 等于原文出域违背工具初衷（G2 §2.1 硬约束）；M2 的 GPU 隧道方案否决（隐私 + 隧道单点，基线 §六#16 + M2 自认 200ms 风险）。
- 附带（M4 可选项）：M3 §2.1 层④「输出侧残差验证器」——在已脱敏出站文本上跑只出 bool 的小模型，把「上游实收零原值」从规则自证变为独立证据。低优先。

**被否选项**：模型替代规则（否，结构化层规则支配）；模型做路由/处置器（否，合规不可解释）；v1 起步即上模型（否——先形态后召回，M2 §5/M3 §8 同判；372 条合成用例训不出可用 NER，训了也是「评测完美、生产撒谎」，M3 §2.1）。

### d. 协议面：v1 只做 OpenAI 兼容；Anthropic 随 M2 必做；Gemini/Responses 条件触发

**决定**：
- **M1 = OpenAI chat completions（流/非流）唯一协议**。请求侧检测面已被 `_aux_texts` 结构无关覆盖（M1 实测 `instructions`/`system` 命中）；响应侧还原复用基线现成链。
- **M2 = Anthropic `/v1/messages` 必做**（请求侧检测白送；响应侧新增：`content_block_delta`/`input_json_delta` 形状还原 + event-stream SSE 解析组帧，M1 差异二列举的形状、M2 实测当前零还原）。理由：Claude Code 类是首要商业 agent 目标且走 Anthropic 协议。
- **Gemini（`candidates[].content.parts[].text`）与 OpenAI Responses API（`response.output_text.delta`）：条件触发**——触发条件明确为「M2 矩阵中出现使用该协议的目标 agent」，出现即做，M3 窗口；不出现不做。
- 实现形态：把三处薄壳（pipeline 请求遍历 / sse 组帧 / `_restore_choices` 响应还原）抽为**协议适配器接口**（M1 §1.2 定性：引擎内核协议无关，绑死 OpenAI 的只有这三处），新协议 = 新适配器 + 响应还原器，不动内核。

**被否选项**：v1 全协议齐上（否——响应侧逐协议重写是无感壳最大新增工程量（M1 差异二），且矩阵未证需求）；永远只 OpenAI（否——商业 agent 主力协议含 Anthropic，M2 实测现状零还原 = 功能不可用，必须补）。

### e. 性能预算：「无感」的量化定义

**决定**（预算值综合 M3 ≤20ms p50/≤80ms p99、G1 ≤50ms p95、G2 ≤100ms、M2 <30ms 四家提案取严）：

| 环节 | 预算 | 依据 |
|---|---|---|
| 请求侧（检测+脱敏+壳转发）TTFT 增量 | **p50 ≤ 20ms，p95 ≤ 50ms**（≤20KB 请求） | 规则全链实测 19ms/20KB（M1）、≈2ms/2000 字（基线，单机单次）；LLM 自身 TTFT 数百 ms 起（各轨迹共识估算） |
| 大上下文（50k 字级） | 修复 O(k²) 后 **p95 ≤ 100ms** | 修复前实测 417ms@49.8k（M3）；bisect/扫描线修复预估 30ms 级（M3 估算，M0-E5 验证） |
| 流式还原 | 不引入基线语义外的新增用户可见缓冲（≤48 字符候选缓冲 + 命中即冲刷语义原样保留） | 还原 ≈0.26ms/50 占位符/2004 字（基线）、0.99ms/2160 字/540 chunk（M3）——可忽略 |
| 壳层转发（回环一跳/TLS 终结再建） | 单 hop 个位数 ms；MITM 形态须做连接池与会话复用 | G2 §2.4 估算（mitmproxy 量级 1–5ms/hop，G1）；不做复用每连接多付 RTT ~100–200ms（M3 §2.2，估算） |
| NER 段（M4 若立项） | **硬预算 30ms，超限即降级回规则，绝不阻塞** | M3 §2.4；judge 降级纪律先例 |
| 补救重试 | v1 无（只计量+提示） | 秒级重试破坏无感（M1 §2.4） |

**「无感」的操作化定义**＝ TTFT 增量达标 ＋ 用户可见零占位符残留（1.2-#2）＋ 归一化等价还原 ＋ agent 任务正常完成（M2 矩阵验收）＋ 防护状态不无感（托盘/提示告知已脱敏 N 处，G1 拍板②立场：体验无感、状态有感——owner 确认见 5.2-F3）。

### f. 附加裁决：透传形态的功能退化——只变换 + 显式拦截，不路由

**决定**：T2/T3 透传形态下，功能集 = **脱敏 + 还原 + 审计 + 密级显式拦截**；三路由（INTERNET/GOVCLOUD/BLOCK）只在网关自营形态（T1 中 agent 直配网关、上游归我方）保留。密级命中的拦截**必须「有感」**：优先本地代答（用基线代答/文案库，按目标协议合成形态正确的响应，内容为脱敏提示文案）；代答不可行（协议未适配）时回 403。**绝不静默拦截**——「无感」与「静默拦截」语义互斥，静默降级 = 安全策略失效（M1 差异四的三角，本规划取「显式可见」解）。透传形态不注入 AI 生成标识（最小干预；若政务要求全域标识，owner 拍板后加，5.2-F3 附带）。

**被否选项**：透传形态保留政务云腿（否——商业 agent 凭据体系不通，G1/GLM2/M3 一致）；静默阻断/静默放行（否，见上）。

### g. 附加裁决：占位符形态不换；还原兜底 = 计量 + 有界提示，v1 不自动补救

**决定**：
- **占位符形态维持基线现状**（全角标签·digest 形态及整套容错还原面）。M2 实测三形态存活率 16/18、17/18、15/18——差距在噪声内，「选一个更好形态」是伪路（M2 §8 修正①）；换形态将作废 t0_stream 14/14 所钉的全部容错资产。自然语言假值路线（M3 倾向 (b)，附带身份证假值须连地址码+生日随机化否则 10² 暴力可还原的攻击面推断）登记 owner 分叉（5.2-F6），推荐 v2 再议。
- **M0 落地两个十行级还原补丁**（皆有实测泄漏证据，且是计量仪器校准——泄漏率实验离不开能看见泄漏的仪器）：
  1. **标签副索引**：`SessionMapper.lookup` 旁加按 `(ascii化标签, digest)` 的副索引，EN 翻译标签（`〔ID_CARD·…〕`）从泄漏变还原——digest 才是身份，标签只是给模型看的装饰（M1 §2.3，其「性价比最高的单点改动」）；
  2. **裸 digest 检测面**：`tolerant_placeholder_hits` 加「裸 `标签·hex8-12`（无括号锚）」第二正则，查表命中仍是终审闸（与 `mapper.py:161` 防误替机制同构），修复「已坏输出判 PASS」的盲区（M1 §3.5、M2 §3.5 双实测）。
- **把 `tolerant_placeholder_hits` 接成运行时策略**：检测「形状可辨但查表未命中」→ 计数入审计 + （可选）托盘提示「本条 N 处未能还原」——立为**一号运行时指标**（M3 §4.5：可见失败发现率比不可见失败高几个数量级，产品会被前者绑架但必须按后者设计）。
- **结构级重组**（label-digest 拆进表格不同单元格）承认为正则原理上不可救的残余（M2 结论三）：缓解 = 系统提示词注入（**仅作优化不作机制**——M1 四条理由：无注入位/概率服从/长上下文衰减/自指风险；M2 实测注入 6/6 vs 不注入 5/6 的增益）+ 残留率计量披露。注入在 M2 按矩阵逐 agent 实测增益后决定开关。

**被否选项**：v1 自动补救重问（否——无失败分布数据定重试上界（M1 自认），秒级重试破预算；M3 拿到分布后再议，5.2-F8）；更换占位符形态（否，见上）。

### h. 附加裁决：引擎双接法——M1 回环转发，M2 起协议适配走进程内

**决定**：OpenAI 形态流量经壳**转发到本机网关端口**（零引擎改动、多一跳回环；G2 §三主路线起步接法），壳负责注入恒定实例会话头与本地网关 key；非 OpenAI 协议（M2 起）在壳内**进程内 import 引擎库**（recognizers/masking 纯库、只吃字符串——M1 §1.2 定性），协议适配器在壳侧实现。性能不达标（M0-E4 实测）则 OpenAI 形态也收进进程内。

**被否选项**：起步即全进程内（否——放弃「一天出竖切 + 网关验收套件直接罩住」的最短路径，G2）；永久双接法不收敛（否——两套接法两套故障面，M3 按性能数据收敛为单接法）。

### M1：竖切最小回路（约 1–2 周）

**目标**：本机显式代理 + curl 与一个 CLI agent 打通无感往返——T1 形态端到端成立。

**改动面**：
- 新建 `anongw-transparent/`（与 gov-anon-gateway 同级）：壳代理（回环 HTTP 监听、流式转发中继）、安装实例标识生成与保管、**恒定注入 `x-anongw-session-id` 头 + 本地网关鉴权头**、运行时泄漏计数器（调 `tolerant_placeholder_hits`）；
- gov-anon-gateway：仅配置层——实例会话的映射 TTL/容量策略（具体配置项实施时核验；基线 §六#12 明示 TTL 两层口径未互证，属待复核项）；
- 新增 eval：`t1_shell`（壳单测：头注入、转发保真、流式中继）、`t1_roundtrip`（多轮一致/还原/泄漏计数）。

**验收标准**：
1. curl 三轮对话：同值占位符恒同（值级语义生效）；还原文本与原文**归一化等价**；泄漏计数 = 0（本地模型腿）。
2. zcode 与 kimi 至少其一，baseURL 指向壳，≥20 轮真实使用：任务正常完成；用户可见输出零占位符残留（日志侧计量）；审计落库零明文（m7 口径抽检）。
3. 引擎回归：m3_masking / t0_stream / t0_gateway / m7_audit 重跑 exit 0。
4. TTFT 增量 p50 ≤ 20ms / p95 ≤ 50ms @ 20KB（E4 完整版）。

**依赖**：M0 全部；owner 提供本地网关 key 配置方式（不入仓）。

### M2：商业 agent 适配矩阵（约 2–3 周）

**目标**：T2 形态落地 + Anthropic 协议 + 大上下文性能修复；产出逐 agent 适配矩阵。

**改动面**：
- `anongw-transparent/`：wrapper 启动器（.cmd/快捷方式：env 代理 + 按运行时 CA 变量 + 拉起目标 app）；CONNECT MITM 与按运行时 CA 分发；**Anthropic 协议适配器**（进程内接法：请求检测复用引擎、响应 `content_block_delta`/`input_json_delta` 还原 + event-stream 组帧）；矩阵记录器；
- gov-anon-gateway：`recognizers/rule/detect.py` `_overlaps` O(k²) 生产修复（E5 原型转正）；三薄壳抽协议适配器接口（`gateway/pipeline.py` / `gateway/sse.py` / `_restore_choices`），OpenAI 行为不变；
- 新增 eval：`t2_matrix`（逐 agent）、`t2_anthropic`（形状还原 + 流式）、`t2_largecontext`（50k 字夹具）。

**验收标准**：
1. 矩阵 ≥ 2 个真实商业 agent 端到端打通（含至少 1 个需 T2 层接入的），每 agent 一页矩阵记录（接入层/CA/QUIC/pinning/协议/结果/边界）归档；pinning 命中者进排除名单并明示。
2. Anthropic 形状往返：流式还原逐块正确、占位符残留率 ≤ 2%（1.2-#2 口径，E2 定标后可调）。
3. 大上下文：50k 字合成夹具 p95 ≤ 100ms（修复后）。
4. 注入增益实测：逐 agent 有/无系统提示词注入的存活率对比，据此定开关默认值（仅优化位，三 g）。
5. 引擎回归同 M1-#3 外加 m4_routing（网关形态未被适配器重构破坏）。

**依赖**：E1 结论、owner 的 agent 清单（5.2-F4）、E5 原型。

### M3：会话与流式完善（约 2 周）

**目标**：把映射与流式的「长期无人值守可用性」补齐。

**改动面**：映射持久化 + **DPAPI 静态加密**（`session_map` 存储层包装；GLM1 §4.4「便宜的正解」）+ 保留/淘汰策略配置；长连接/keep-alive 与多路复用下的 SSE 中继稳健性；流式吞吐压测工具；（条件触发）Gemini / Responses 适配器；（owner 确认后，默认关）原文格式回填开关——存原文格式用于回填会让映射变大且须重验审计零明文口径（G2 §2.3，连动回归）。

**验收标准**：跨进程/跨重启同值恒同（持久化生效）；映射文件离线复制后不可读（DPAPI 负例验证）；≥10 路并发长回复流式压测零交叉污染、命中即冲刷语义保持（对照基线 50 并发零串扰口径）；映射加密改动后 m7 审计断言重跑通过；格式回填开关（若开）往返逐格式验证 + 审计零明文复验。

**依赖**：M2；owner 对 5.2-F5/F6 的答复。

### M4：判定增强（条件立项，约 2–3 周）

**目标**：按 E3 证据补开放词表召回；模型永不为可用性背锅。

**改动面**：`recognizers/ner/adapter.py` 接真实模型（现恒 `[]` 占位）；级联触发器（规则未命中且自然语言段）；30ms 硬预算 + 超限降级；**重叠 span 仲裁**（`mapper.py:262` 拼接前置闸，规则层优先/长 span 优先，实施时定并写入 eval）；NER 白名单复刻（基线 0/22 面）；影子模式日志与报表；（可选）输出侧残差验证器。

**验收标准**：影子期报告（真实语料上 precision/recall 对比词表增量净胜才准进主链）；降级路径测试（人为超预算注入 → 主链不阻塞、回落规则）；白名单 0/22 复刻不回归；仲裁 eval（构造重叠 span 夹具）；主链 TTFT 增量仍达三 e 预算。

**依赖**：E3 通过立项门 + owner 语料授权 + CPU 可跑模型到位；与 M5 可并行。

### M5：硬化与交付（约 1–2 周）

**目标**：从「能用」到「敢发」。

**改动面**：覆盖率/状态面板（被处理会话数、泄漏计数、T2/T3 下未覆盖出口提示——复用或轻量新建，不强制 WebUI）；防火墙伴生规则文档化选项（LLM 域名出网仅限代理进程——防绕过移到边界，G1 §2 小结；需管理员，非默认安装项）；安全自查（本地端口最小暴露、映射文件权限、密钥卫生——不引入演示凭据，基线 §六#4 教训）；安装器/wrapper 打包；用户文档（含「装 CA 即有感变更、无感自安装完成后起算」的诚实口径，G2 §四）。

**验收标准**：全量回归 = 基线 16 模块（可跑集）+ 本工具新增 eval 全绿；性能终验达三 e；交付自查清单（含 1.3 排除项的明示声明）逐项勾销；文档含每形态安装/卸载/故障排查（卸载 = 一键可撤销，M1 §2.2）。
