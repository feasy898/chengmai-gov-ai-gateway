# 思考轨迹（GLM-5.3-Flash · 第二路）：从"显式 API 网关"到"无感脱敏工具"，差的哪一环

> **写作声明**：个人原始推理记录，非规划文档。依据仅两份：任务意图原话、《盘点/基线总文-gov-anon-gateway.md》（2026-10-04 定稿，245 行，下引"基线 §X"）；数字均转录注章节，本轮未回读源码、未运行评测（红线：只写本文件）。允许中间结论被后文推翻，文末列自我修正清单。

## 一、问题理解：能力几乎不缺，缺的是三层"形态壳"

**1.1 定位。** 基线 §一：识别→可逆脱敏→敏感度路由→转发→客户端侧还原→输出防护→审计，在 OpenAI 兼容 API 形态下成立，16/16 模块三族实测通过（§三表 A）。对用户意图逐项打钩：识别 ✓（召回 1.0000/618，§2.1）、脱敏 ✓（会话稳定 + 流式 byte-exact，§2.2）、还原 ✓（容错还原 t0_stream 14/14）、审计 ✓（§2.5）。**用户要的四个动作，引擎侧基线都有且经实测——差的不是算法，是形态**：基线假设"流量自己来找它"，用户要"顺路截走流量、用户不需要操作"。

**1.2 第一环：截获与信任（最硬）。** 显式网关的契约是"客户端改 endpoint、带我的 key 和 SESSION_ID"。商业 agent 的 endpoint 在服务方手里改不了，TLS 端到端看不懂，必须本机 MITM：自建 CA + 装进信任链 + 只对目标 LLM 域名分流解密。这环基线完全没有（S3 透明代理 §七#4 登记未开始）。难点不是解析 JSON，是"取得目标应用信任"：Electron/Chromium 系多数尊重系统 CA；Node CLI 默认用内置 CA bundle（要 NODE_EXTRA_CA_CERTS 才认自建 CA）；Python certifi 不认系统证书池；少数应用证书固定（pinning），固定了就无解。我的判断：**"对商业 agent 有效"能否兑现，不取决于引擎，取决于目标 agent 的 TLS/代理行为**——该是第一个实验（§三）。

**1.3 第二环：会话语义要从"客户端告知"变成"旁路推断"。** 基线占位符稳定性（同会话恒同、跨会话互异，m3 9/9，§2.2）与属主绑定（§2.8）都建立在显式 SESSION_ID 上。无感形态没人传——必须从流量推断会话，候选键 =（域名 + API key 指纹 + 首条用户消息哈希 + 时间窗口；商业 agent 多轮重发全量历史，首消息哈希很稳）。关键不对称性：**会话断错 = 旧占位符在新会话无映射、原样出网——占位符是哈希串，不泄漏，只是 LLM 看不懂、回答变差；会话并错 = A 的手机号还原进 B 的对话——安全事故**。所以会话键必须"宁可断、不可并"，fallback 一律朝"漏还原"倒。

**1.4 第三环：渗漏直接打在用户脸上。** API 形态还原结果给自家 WebUI，小瑕疵可忍；无感形态客户端是商业 agent 的渲染层，用户盯着屏幕看对话。两个新"有感"来源：其一，基线还原是**归一化等价**口径（`138 0013 8000` 回来变 `13800138000`，§2.2 口径节、§五#6）——程序无所谓，人眼看自己号码变格式就是"工具改了我的东西"；其二，模型侧改写占位符（改大小写、翻译标签、塞进代码块）——基线 tolerant restore 有 fuzz 底子（§2.2），但真实模型会造出夹具外的变体。**"无感"的产品上限由回写层鲁棒性决定，不由识别召回决定。**

## 二、方案空间

### 2.1 判定层：规则已打满结构化层，小模型的真实战场只有开放词汇

基线事实：规则+校验位+词表三层，结构化号码召回 1.0000（618/618）、白名单误报 0/22、2000 字 ≈2ms（§2.1、§三表 B）；弱点：NER 恒空、人名仅 4 演示名 + 姓氏启发式 0.5 置信、住址零产出、密级词表仅 6 词（§五#1、§六#9）；且召回数字全来自合成语料、不能外推真实分布（§六#8）。

我起初想"小模型要不要整体替代规则"——后来意识到是伪命题：身份证/手机号/信用代码这类带校验位的结构化实体，规则是**支配性**的（召回 1.0、2ms、可解释、零模型依赖），小模型无增量还引入不确定性。**小模型唯一真实价值在开放词汇实体**：人名、住址、机构名、自由文本项目代号——恰是基线自认的洞，也是 §七#4 中 S4（真实 NER）的位置。正确的问题不是"规则 vs 小模型"，是"放哪一环"：

- **(a) 请求级二值判别**——否。判别完还得抽取，串联时延与错误率双输；"JEV 式判别器"用在请求级就粒度错了。
- **(b) token/span 级抽取器**——正确位置。直接产出"实体+类型+边界"，喂进与规则相同的 masking 管线，可逆/审计/路由全复用，一步到位链路最短。
- **(c) 语义敏感度判定**（路由增强）——非关键：无感形态下路由矩阵本身退化（见 2.2 末尾），优先级低。

**硬约束推论**：NER 输入就是原文，做成云 API 等于原文出域，违背初衷——必须**本机推理**，尺寸钉死在 CPU 可跑量级（量化后 <100M 参数；本机无独显，:9004 隧道单点风险，§六#16）。ONNX + INT8 + 截断滑窗估 50–200ms/2000 字，比规则慢两个数量级，但相对商业 API 的 TTFT 仍是小头——前提是**与规则并行跑再合并，绝不串联**。

精度标准：脱敏场景**漏报 >> 误报**（漏报 = 原值出网 = 事故；误报 = 多脱了 = 用户有感），阈值偏召回；误报失控同样破产"无感"——基线白名单（0/22）须在 NER 层复刻（"海南省教育厅"不能被切出来替换）。验收不是学术 F1，是**真实语料漏检率 + 误报致用户有感率**。

结论：**规则为主、NER 为补**——自由文本层规则先扫、NER 并行补漏、并集进管线；若真实流量开放词汇占比很低，NER 降 P2 甚至不做，交 §三实验 3 证伪。

### 2.2 部署形态：五种过一遍

- **网关 API 模式（基线现状）**：只覆盖"自己代码调 LLM"，对不可改 endpoint 的 SaaS agent 无效；但须保留作回归基床——无感壳的单测都应打在这层之上。
- **本地显式代理（HTTP(S)_PROXY）**：我起初以为显式代理不用碰证书，后来想清楚：不解密 CONNECT 隧道就什么都看不到，**CA 信任是一切代理形态的共同前提**，显式与透明的差别只在"流量怎么到代理"与"故障半径"。显式代理按进程作用域：工具挂了只是 agent 直连失败，不会全网断网；安装 = 设变量+装 CA。CLI 类商业 agent 普遍尊重代理变量。
- **本机透明代理（SNI 分流 + CA）**：覆盖不尊重代理设置的应用，代价是流量重定向（要 WinDivert/WFP）与更大故障半径。**必须按域名白名单分流**：只有目标 LLM 域名进 MITM，其余直通——否则工具一挂用户全网断，"无感"变"全感"。基线 S3 规划的正是这一形态（§七#4），引擎现成，壳是新的。
- **浏览器/IDE 插件**：MV3 拦不了响应体，要 content script 在 DOM 上还原，与站点结构耦合、脆；网页端还原发生在渲染之后最难做干净；IDE 插件够不着终端 agent。作补充不作主路。
- **SDK 封装**：只对自研应用有效，优先级最低。

**主形态判断**：显式代理先行（快、窄），透明代理按需增强（慢、宽），共用同一引擎与 CA，信心约七成。

**再挑明一处退化**：三路由（§2.3）的"政务云腿"要求改发政务云 endpoint——商业 agent 的会话、计费、鉴权全绑在商业服务上，代理改目标语义风险高；无感形态下路由实际退化为 **BLOCK（拦截/代答）或脱敏后直通**两路 + 审计；伪装回商业 API 格式技术上可能，只配远期选项。

### 2.3 回写层：占位符形态学、会话推断、注入可靠性

**占位符设计**。两条要求：对 LLM 语义透明（模型理解"这是个手机号"才能正确完成任务）、抗改写（模型不乱动它）。带类型标签的形态（如 `[[PHONE_xxxx]]`）利大于弊，但中文标签在英文任务里更易被翻译/改形，tokenizer 也可能切碎——全可测。**系统提示词注入占位符规则：有用但不可依赖**——agent 的 system prompt 栈很长，注入段权重被稀释；多轮中是否保留由它决定；对 reasoning 模型还烧 token。真正保障在还原侧 tolerant matching（§2.2）。

**会话一致性**（1.3 已析键设计，补三面）：
- **跨请求**：agent 多轮重发全量历史，占位符反复出现——利好，命中即替换；但占位符可能被写进 agent 的 memory/todo/代码文件，隔天引用时映射若已 TTL 过期（§六#12），还原断链——session_map.db 明文落终端，风险升级（§六#6），**持久映射必须本机静态加密，保留期需拍板**。
- **流式**：chunk 切占位符基线已解决（500 组/例 fuzz byte-exact、缓冲 ≤48 字符，§2.2）。新增工作量在协议侧：各家 SSE 帧互异（OpenAI/Anthropic/Gemini 不同）、可能 gzip/brotli（解压改写再压）、可能 HTTP/2 甚至 QUIC（走 UDP 绕过代理；是否阻断 443/UDP 迫使回落 TCP 本身会"有感"，要测）——基线只对 OpenAI 兼容流实测过，**多协议适配是无感壳的主要新增量**。
- **格式回填**：归一化等价在无感形态下"有感"（1.4），可考虑映射表存原文格式回填——代价是映射表变大、审计零明文口径要重验（§2.5 的 0/7 基于现行映射语义），要连动回归。

### 2.4 性能预算：无感 ≈ TTFT 增量 ≤100ms

无感的对照物是"即时感"阈值；更贴的指标是 TTFT（首 token 延迟）增量——商业 API 的 TTFT 通常数百 ms 起，**网关增量 ≤100ms 可视为无感**。分解：规则检测 ≈2ms ≈ 免费；CPU-NER 50–200ms 是唯一大头，必须量化+截断+并行；代理壳（TLS 终止/再建、解压、SSE 帧改写、跨帧 48 字符缓冲）同机回环应个位数 ms；流式还原 0.26ms/2000 字级不构成瓶颈。真正未测的是代理壳**吞吐**：长回复每秒数千 token 边收边转，不能整段缓冲——要单独压测。

## 三、最可能成功的路线与证伪实验

**主路线（信心 ~70%）**：基线引擎全量复用 + 本机显式代理壳 + OpenAI 兼容协议先行、逐家适配 + 规则层独走、NER 待实验定夺。壳与引擎接法：进程内 import 基线库 vs 转发到本机现有网关端口（零改动、多一跳）。我倾向**起步用后者**——一天出垂直切片、验收模块罩住，性能不达标再收进进程内。

**备选 A（信心 ~55%）**：若真实流量以自研应用为主，基线 API + SDK 已是答案的九成，无感壳降为锦上添花——取决于流量构成，需人类拍板。
**备选 B（信心 ~40%）**：驱动级透明代理全量接管——工程重、蓝屏级故障半径、管理员权限与驱动签名是现实障碍，只在硬需求时上。

**证伪实验**（按性价比排序，一至三天级）：
1. **适配矩阵实验（证伪主路线，最优先）**：对点名 agent 实测：尊重系统代理/HTTP(S)_PROXY 吗？装自建 CA 后握手成功吗？走 QUIC 吗？有无证书固定？输出支持矩阵——若全数 pin 且无代理选项，主路线当场降级。
2. **占位符鲁棒性实验（不依赖部署）**：向真实商业模型发带占位符的多轮对话（复述/翻译/写进代码块/长上下文回指），对照注入 vs 不注入，统计改形率与还原召回。改形率 >5% 且修不回来，回写层重设计。
3. **NER 缺口量化实验（决定 S4 立项）**：取 20–50 份有授权真实政务文本跑规则层，人工标注漏检的开放词汇实体占比。占比低则小模型不做，集中于人名/住址则确认优先——同时正面校验"合成语料不能外推"（§六#8）。
4. **延迟实测**：垂直切片打真实商业 API，量 TTFT 增量与流式吞吐，超标再优化。

## 四、风险、未知、需拍板的分叉

**风险**（按杀伤力排序）：
1. 目标 agent 证书固定 / 不开放代理设置 → "对商业 agent 有效"砍半甚至清零。缓解：实验 1 前置，承诺按矩阵开。
2. 占位符渗漏到用户可见面（改形、还原断链、被写进文件）——"无感"破产第一来源。
3. 会话误并 → 错误还原（A 的值还进 B 的对话），事故级；会话键必须保守。
4. 本机部署放大基线已知风险：映射库明文落终端（§六#6）、演示 key 可过鉴权（§六#4）、工具自身成本机攻击面（§六#3）。
5. **在未冻结基线上叠加**：§七#1 记 36 文件未提交，§七#2/#3 记 gate_final 两轮 1/9、2/9 FAIL 且失败点漂移——回归基线是晃的，出了问题责不清；冻结快照应是无感壳动工前置。
6. 合规：MITM 用户流量、改写用户内容、持久化映射——政务终端的告知义务与审计要求能一票否决。

**我不知道的事**：真实流量开放词汇实体占比（决定 NER 立项）；用户对"安装即知情"的接受度——装根 CA 本身是一次有感变更，"无感"只能从安装完成后起算；目标 agent 的 TLS/代理行为（实验 1 可消）。

**需人类拍板的分叉**：
1. 目标 agent 清单与优先级（圈定适配矩阵）；
2. NER 失败模式：fail-open（按规则层结果放行）/ fail-closed（拒绝转发）/ fail-delayed（延迟转发）——政务场景我倾向后两者，但这改变可用性承诺；
3. 映射表保留期与加密策略（跨会话便利 vs 本机静态风险）；
4. "无感"的合规边界：安装时显式告知+常驻托盘指示是否必须；
5. 先显式还是直接透明代理（快窄 vs 慢宽）。

## 五、自我修正清单（被我自己推翻的中间结论）

1. 起初想"小模型加持整个判定层"→ 修正：规则在结构化层支配性成立，小模型只补开放词汇，立项与否取决于真实语料缺口量化（实验 3）。
2. 起初以为显式代理可绕开证书、全量截获更彻底 → 修正：不解 CONNECT 就看不到内容，CA 信任是一切代理形态的共同前提；按域名白名单分流收敛故障半径，否则工具故障 = 用户断网。
3. 起初把"跨会话还原"当纯增益 → 修正：基线跨会话互异 + TTL 是有意的安全属性，打破它必须连着静态加密与保留期重设计。
4. 起初默认三路由照常成立 → 修正：政务云腿对商业 agent 不可表达，路由退化为 BLOCK / 脱敏直通两路。
5. 起初把"JEV 式极快判别器"理解为请求级分类 → 修正：正确粒度是 span 级抽取（串联方案时延与错误率双输），"快"靠并行合并而非前置短路。
