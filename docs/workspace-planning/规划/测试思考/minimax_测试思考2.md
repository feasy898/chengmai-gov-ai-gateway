## 0. 三个实测事实（它们改写了「测什么」）

**(0.1) 基线 16/16 在本机不能直接复现，但失败的 19 项里 0 项是代码缺陷。**

```
python wf_run.py venv -m evals.m3_masking → exit 0，M3 MASKING: 9/9
python wf_run.py venv -m evals.t0_stream  → exit 1，5/14
python wf_run.py venv -m evals.t0_gateway → exit 1，1/15
```

`t0_stream` 失败首项是 `RuntimeError: port 8901 already occupied`（`evals/t0_gateway.py:98-101` 的 `_assert_port_free`），后 8 项 `KeyError: 'srv1'/'app'/'cfg'` 全是级联。`netstat`+`wmic` 查到占用者：`20528 -m gateway.mock_upstream --port 8901`、`27076 --port 8902`、`28004 -m evals.m10_e2e`。**基线 §六#17 不是历史记载，是当下正在发生的。** 含义比「注意串行」强：端口必须由测试自分配（`common/config.py:93-104` 的 `ANONGW_*` 覆盖支持注入 `upstreams` 整段），并有「冲突重试 + 打印占用者 PID 与命令行」的 fixture。**一个在别的批次还在跑时给出 9 个 KeyError 的套件不能当门禁。**

**(0.2) 规划 §三 g 的「裸 digest 检测面」方向对，但单纯加第二正则会误报。**

我拿现状 `tolerant_placeholder_hits` + 手写裸正则探了 11 条真实政务文本（sha1 / 工单号 / commit hash / 预算金额）：裸 hex 单独几乎不误报（缺「标签·」结构）；真误报面在**「已知中文标签+分隔号+8-12hex」**，而我构造的 `〔附件·1a2b3c4d〕` 就被现状检测面报成泄漏（`evals/t0_stream.py:688-691` 已留同类负例）。故断言须**两级**：`形状可辨`（披露口径，进计数）+ `查表命中`（处置口径，进告警），不能是一个布尔。这直接决定 T6 的结构。

**(0.3) 规划 §1.2-#2「残留率 ≤ 2%」这条验收级定义，现状测不出来——7 个真实坏形态里 5 个判 PASS。**

拿真占位符 `〔手机号·d5a92194〕` 构造 7 种改形，用现状断言（`ops/e2e_smoke.py:1348-1349` 那条）判：

| 形态 | 旧断言 | 用户实际看到 |
|---|---|---|
| 表格拆列 | **PASS(假绿)** | `\| 手机号 \| d5a92194 \|` |
| 括号被剥 | **PASS(假绿)** | `手机号·d5a92194` |
| 分隔号变冒号 | **PASS(假绿)** | `〔手机号: d5a92194〕` |
| 16 位扩写 | **PASS(假绿)** | `〔手机号·d5a92194d5a92194〕` |

## 1. 从 a–h 推导「什么算测过」

对每条裁决问：**违反了它，用户会看到什么可观测的错误？** 答得出的才是测试点。

**a 形态**。违反表征 = 流量没进工具（静默部分覆盖，规划 R2）。仪器已有：mock 上游 `RingBuffer.texts()`（`gateway/mock_upstream.py:126-138`）供 bytes 级扫描，`e2e_smoke.py:1359-1360` 正是用它做「上游实收==脱敏版+零原值」。**两跳都要扫**（壳→网关、网关→mock）。T2/T3 另需「未覆盖出口能被工具自己说出来」（规划 1.2-#5）——**且必须有负控**：走代理的请求计数必须增长，否则「如实报告未覆盖」可靠「什么都不报」作弊通过。

**b 值级键**。实测语义后果：同 instance 两个对象→同占位符；换 instance→不同；**三个「会话」全塞同一 instance 时 `all differ=False`，而基线语义为 True**。

**这是全文第二关键判断：m3 的 `mask:stability-1000`（`evals/m3_masking.py:124-126`「3 cross-sessions all differ」）在值级形态下必然 FAIL，且是语义反转不是缺陷。** 规划 §三 b 说基线会话语义原样保留、两形态并存——那么测试必须**分属两个 eval，绝不能改 m3 断言让它变绿**：改断言 = 悄悄删掉基线的抗链接属性（`mapper.py:9-10` docstring 写明是设计意图）。新工具另立 `t1_valuelevel` 断言反向不变量。文档里建议写成**语义对照表**（基线断言 X，新形态断言 ¬X），让评审看出是设计变更。

**c 判定层**。规则层 618/618 直接搬。但无感形态给它一条基线没有的要求：**误报在显式网关里只是路由选择，在无感形态里是用户看到自己说的话被无端替换**。故须加**零敏感实体请求的端到端逐字保真**（基线 t0_stream `step_stream_clean` 只做了单轮 mock）。NER 若 M4 立项，仲裁夹具**必须 M0 就写好并标 skip**——M4 才写就会照着实现写，变成应试。

**d 协议面**。`_restore_choices`（`gateway/pipeline.py:828-853`）只认 choices；`sse.py:61` 按 `data:` 行解析且「`data:` 以外跳过」（`sse.py:70`）。故 Anthropic 第一个必测行为是**保留 event 名并据此选 delta 路径**（其 event 名有语义），第二个是 `input_json_delta` 的 hold-to-finish（OpenAI 侧该能力基线已有，`m3_masking.py:370-392` 三项全绿，断言逻辑可复用）。条件触发的 Gemini/Responses：**写占位但禁跑的模块**（存在、exit 0 报 SKIP 及原因）——先例是基线 §七#6 的 `u8_repro`/`m8_quality` SKIP 争议。**占位让「没做」变成可见的一行，而不是沉默的缺席。**

**e 性能**。见 §5。

**f 透传退化**。「绝不静默拦截」需负控：密级命中时上游**确实收到**请求，客户端拿到**形态正确的代答**（Anthropic 下也得是 `content_block` 形状）。基线 m4「BLOCK 恒 null upstream」在透传形态下是**错误断言**——与 b 同类问题。

**g 形态不换**。T8.4 目录是资产来源，但**我实跑发现分叉**：t0_stream 内联 23 形态（`t0_stream.py:615-647`）、m3 内联 15 形态、spec 写 11（`docs/assets/specs/masking-placeholder.md`），内容也不同（t0 多出 bullet/ascii-dot-sep/confusable-l/backtick-inside）。对应基线 §八#5「四套记录」，**但这是实际分叉不只是文档滞后**。→ 收敛为单一数据源，否则 T6 会继承分叉、三套变四套。

**h 双接法**。两接法**可观测差异只有性能** → 须有**接法无关性断言**：同夹具两接法 byte-exact 全等（基线 t0_stream 500 组 fuzz == 整段的方法论）。有了它，E4 决定收敛只需换配置。

## 2. 分层：开发者可见 vs holdout

**判据**：若一个用例的字面内容（具体占位符串、具体表格模板、具体 agent 名、具体 hex）出现在开发者阅读范围内，它就不再测泛化，只测记忆。

**三类天生保密**：① 具体破坏实例（哪个改形×哪个位置×哪个密度）② 分布形状（真实语料占比——规划 E3/F7 就是这条）③ 评分口径边界（什么算泄漏）。

**反之机制类知识必须公开**：`canonical_placeholder` 四步（`mapper.py:110-135`）、改形分类学（噪声/转写/结构/语义）、48 字符窗的由来（`remap.py:44`）。开发若不知道「结构级重组不可救」，会去写救不了的东西。**分类学公开、实例保密**——这是边界的具体形状。

**哪些一旦看见就会应试**：

- **形态枚举表**。t0_stream 的 23 条对开发者**完全明文可见**（`t0_stream.py:615-647`）。这是**已发生的过拟合**：照目录实现→目录全绿→真实模型照样漏。我在 0.3 测出的 5/7 假绿就是它的后果，**不是假设风险**。对策不是隐藏 t0_stream（它钉不回归，有价值），而是 holdout 另立不重叠目录回答「你的覆盖率是多少」。
- **注入文案**。规划 M2-#4 测有/无注入存活率；若两组写在一个函数里，文案会被调到「恰好让这 6 个任务活」。MM1 §2.3 已论证自指风险（注入示例里的假身份证会被自己的规则层脱敏）→ **最终文案由不懂实现的人写，且测试方提前看不到**。
- **性能夹具字节**。公开即可压缩作弊。构造规则与 seed 保密，只公开阈值。
- **真实 agent 名单**（规划 F4）。清单先给开发者，E1 矩阵就退化成逐个打勾，失去「哪些 agent 根本做不到」这个信息（规划 R3 的关键）。

**holdout 五类泛化面（怎么造 + 怎么评）**：

**(i) 真实语料分布——这一类我造不出来。** 规划 E3/F7 与基线 §六#8 指向同一件事：无 owner 授权的 20–50 份真实文本，任何 holdout 语料仍是合成的。**F7 落地前本组是空的，测试文档必须如实写「暂缺，依赖 F7」**，而非用合成语料假装填上。能给的是接口：`holdout/corpus/<授权批次号>/` + 无授权时该组 **DEFERRED**（沿用 `ops/e2e_smoke.py:446-448` 的惯例，DEFERRED 不计失败不影响退出码）。

**(ii) 未见过的 agent/协议变体**——**生成而非枚举**：从协议形状语法（Anthropic 事件类型集、Responses 的 `response.output_text.delta`、Gemini 的 `candidates[].content.parts[]`）程序化合成（不同 delta 粒度/分块边界/stop 序列/usage 位置）。**评分三档**：① 完全等价 ② **归一化等价**（基线 §2.2 口径，规划 §1.2-#3 已裁定用它，**不采逐字全等**）③ 不可接受。三档制防「用逐字全等逼出无意义的格式敏感」。

**(iii) 对抗性改写**——见 §4，是主战场。

**(iv) 长上下文**。实测 `_overlaps`（`recognizers/rule/detect.py:339-340`，对 `taken` 线性扫）：

```
固定密度扫长度：7600字/400实体 37.4ms → 15200/800 48.7 → 30400/1600 131.4
              → 60800/3200 458.2 → 98800/5200 1149.2ms（11.6 µs/字）
固定 30400 字扫密度：1419 实体 81.4ms(0.057ms/实体) → 1563 实体 197.0ms(0.126ms/实体)
```

**每字成本 3.2→11.6 µs、每实体成本 0.057→0.126 ms，两轴都恶化 = 长度×密度交叉项。** 与 M3 实测（49,800 字/3000 实体 417ms）量级吻合，也说明 M2「20k 近线性 1.3–1.9 µs/字」只在其低密度夹具成立。**故 holdout 长上下文须把长度与实体密度当两个独立自变量分别扫**——只扫长度会漏掉密度轴（规划里没有这一点）。p95 ≤ 100ms @ 50k（规划 §三 e），超了即 E5 原型失败。

**(v) 多轮漂移**。值级键**结构性消灭**会话漂移（这也是它被选中的理由），故要钉的正是「漂移不可能发生」：同值在第 1 轮与第 200 轮、跨历史压缩、跨重启、跨 agent 切换恒同；反向（跨 instance 必异）同样要钉。**但有一个漂移面值级键管不了：模型侧记忆漂移**（多轮里模型把占位符改写成前文提过的另一个）。必须 holdout，因为它依赖模型真实行为。

## 4. 对抗矩阵：把 MM2 的存活率问题变成用例

**四轴**（**域的边界公开，域内实例保密**）：

- **形态轴**（分类学，公开）：*噪声类*（括号内外反引号、空白换行——已被 `mapper.py:120` 第①步覆盖）｜*转写类*（全半角、大小写、0/O 1/l、同形括号〔【〖［[、间隔号 ·・•‧⋅﹒．.——已被第②③步 + `_DIGEST_CONFUSABLE` 覆盖，`mapper.py:131`）｜*前缀并入类*（`〔主号：手机号·…〕`——已被 `_strip_prefix_segments` 覆盖，`mapper.py:97-107`）｜*结构/语义类*（拆列/剥括号/换分隔号/扩写/翻译标签/幻觉摘要——**现状部分未覆盖**，0.3 实测）。**前三类必须公开（是机制知识），第四类的实例进 holdout。**
- **操作轴**（公开任务词表）：复述/表格/列表/引用/翻译/摘要/JSON化/代码块/计数/改写——沿用 MM2 §3.3 的任务定义但**换全部实例与措辞**。
- **位置轴**：句首/句中/句尾/表格单元格/代码围栏内/列表项内/工具参数 JSON 内/与相邻占位符紧邻。
- **密度轴**：单/20/200 个——单列是因为**相邻占位符会互相干扰候选缓冲**（`remap.py:103` 的提前释放分支）。

**评分三档而非一个数**。规划 §1.2-#2 的「残留率 ≤ 2%」隐含前提是「分子=检测面报出的数」，而 0.3 已证明补丁前分子恒零。故每例归一档且**能追到具体形态**：

- **S1 可还原**（查表命中→用户见原值）｜**S2 不可还原但形状可辨**（检测面报出→可计量/可披露/可提示，正是 §三 g 要接运行时策略那类）｜**S3 不可还原且形状不可辨**（连计量都做不到）｜**S4 误替**（不该还原却还原了）

**S4 必须在 holdout**：误替代价（把 A 的手机号还原到 B 的位置）远高于漏替。且 S4 有个方向：**同段文本放两个不同会话的同值**——会话级下占位符不同，值级下**相同**（实测确认），故值级形态 S4 风险面变大。这是 b 裁决已知并被 F2 接受的属性，但**测试要如实记录这个面**，不能装作没有。

**三类「补全/幻觉」的处理**：

- **补全成更完整的东西**（16-hex 扩写）：现状检测面 MISS。**正确答案是「不还原、原样放行 + 计数」，不是「截断到 8 位试试」**。故断言要钉的是**不误还原**（不能还原出一个错误的原值）——即 S4 面。**且须写死「不得截断匹配」**：扩写形态让这种取巧实现有了可攻击面。
- **幻觉出原值**（`〔身份证·dead〕`，6-hex）：现状 MISS 且形状不可辨 → S3。**这里我要说一个可能不受欢迎的判断：这一类的正确测试是「承认测不到」。** 任何声称能测到它的断言，要么在测一个不可能达到的性质，要么在等模型恰好不那么做。应把 S3 单列一行、如实写「irreducible loss」（基线 `evals/u8_repro.py` docstring 已用同词自注），**而非混进残留率分母稀释掉**。这是「不骗人」在测试层的应用。
- **EN 标签翻译**：MM1 §2.3 判其为最高频。我实跑真实模型（`:9004` local-chat-8b，在线）复现：

```
[translate] 客户端实际看到：
 '...“手机号·8d69653f”看起来像是一个模板占位符...'
 '| 标签 | 手机号 | Phone number |'   '| 标识符 | 8d69653f |'
```

**模型自发把标签与 digest 拆进表格不同单元格**（MM2 §3.3 结论三的结构级重组）——而我只说了 translate，没让它用表格。**且括号被剥了**，故现状检测面 MISS。**一个真实模型的自然行为同时命中两个盲区** → holdout 必须含**混合破坏**用例（多形态叠加）。理由：单形态测试会让开发修完一个还剩一个，而真实模型是**同时**干两件事的。

同模型 6 任务各 1 次：`table`/`list`/`json` 返回空串（`survived=False leaks=0`），`quote`/`translate`/`summarize` 存活并还原。**空串本身是测试设计信号**：可能是内容过滤（基线 `thresholds.py:101-102` 的 code=1301 有界重试口径）也可能是拒答。**断言必须能区分二者，否则会写出把拒答当通过的用例。** 我未深究（超本次范围），列入开放问题。

## 5. 性能与无感：怎么测才不抖

**实测噪声结构**（同一 2000 字夹具 detect）：

```
no-warmup   n= 30  p50=0.071  p95=0.168  p99=11.115  max=11.115  mean=0.446
with-warmup n=300  p50=0.066  p95=0.093  p99= 0.113  max= 0.125  mean=0.071
前 5 次无预热：['11.11', '0.17', '0.08', '0.09', '0.07']
```

**第一发 11.11ms vs 稳态 p50 0.066ms = 168 倍。** 基线 `m2_recognizers` 取「10 次均值 < 100ms」（`m2_recognizers.py:266-272`）——均值被污染 6 倍，但因阈值比 p50 大三个数量级**没假失败，这是宽松阈值掩盖了粗糙方法，不是方法对**。

**建议（= 规划 E4 / GLM2 四实验之四）**：

1. **预热显式且被断言钉住**：≥5 次预热不计，再采 ≥30 次。基线 `m3_masking.step_performance` 跑 50 次取均值（`m3_masking.py:587-622`）无显式预热，因 restore 不涉冷编译路径才没暴露。**新组须把「预热后 p99 / 无预热 p99」两个数都打出来**——该比值本身就是环境健康度指标。
2. **测「增量」的定义要钉死**：同请求、同进程、A/B 对照（A 直连 mock，B 过工具）取差值 p50/p95。B 的绝对值会被 mock 冷启动、网络栈、连接池等与被测物无关的因素污染。**基线 `thresholds.py:8` 的 `GATEWAY_OVERHEAD_P95_MS = 150` 我 grep 过，全仓只有定义没有使用**（仅 `out/public-export/` 有拷贝）——**是死阈值，别当参照物**。
3. **CI 不打抖四条**：① **双档阈值**——`HARD`(p95≤50ms，规划值) 与 `ADVISORY`(≤80ms) 间设 WARN 带，WARN 不失败但进日志并显式列出；**n=30 时 p95 统计噪声很大，用统计不稳的量做硬门 = 制造 flaky，而 flaky 门的真正代价是大家学会忽略它**。② **有条件重试**——超标自动重跑一轮（基线已有 1301/空回复的有界重试先例，`thresholds.py:101-102`），**重跑仍超才 FAIL，日志必写「首跑 X / 重跑 Y」**；无条件重跑 = 藏失败。③ **前置自检**——跑前 netstat 确认无他批占端口（0.1 那个问题），性能被并发负载污染时数字无意义；建议性能组独占端口段。④ **夹具保密 + 每次重建**，避免被缓存成 LCP-friendly。
4. **补一个基线没有的面：还原侧分块粒度敏感度**。规划 §三 e 说「流式还原不引入新增用户可见缓冲」，怎么测？**测「首个 delta 到达客户端的时刻」在有无占位符两种情况下是否相同**——若还原层攒够 48 字符才发，首字延迟就会随内容波动。基线有「命中即冲刷」语义，但**没有一条断言直接测「首字节延迟与内容无关」**。这是读规划时发现的测试空白。

**「无感」怎么测**。规划 §三 e 是五项合取，前三项已覆盖。第四项「agent 任务正常完成」有陷阱：**双层**。可自动的下界——fixture 任务集带**可判定成功条件**（从 5 个候选选出正确项 / JSON 合法且字段齐全），且**任务须要求模型用工具调用**（这样「工具参数还原正确」才可断言，基线 `m3_masking` 三项 tool 检查可复用）。**分母不该是「任务全对」**（模型能力波动），而是「**工具参数还原错误次数 = 0**」——后者才是被测物负责的。不可自动的上界——真实 agent 20 轮（规划 M1-#2）**如实标半自动 + 人工抽检表模板**，不写成 exit 0 的自动断言。基线先例：`m8_quality` 记「质量比」这种需解读的数（`thresholds.py:76`）。

## 6. 目录、命名与优先级

沿用基线约定（`python -m evals.<模块>`、exit 0、日志落 `tmp/wf/`、阈值集中 `thresholds.py`「禁止在用例里散落魔法数字」，`thresholds.py:1-4`）。新工具是独立包（规划 §四 M1「与 gov-anon-gateway 同级」），故**独立仓 + 独立 evals，但经 PYTHONPATH 复用引擎库**（与规划 §三 h 进程内接法同思路）：

anongw-transparent/

    t1_roundtrip.py    # T3 端到端：多轮一致/归一化等价/泄漏计数
