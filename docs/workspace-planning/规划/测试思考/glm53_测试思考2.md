## 〇、动笔前的自我定调

我给自己立的第一个判据：**测试设计的目标不是"证明它能用"，而是"让每一句验收话都有人咬住"**。规划 §1.2 已经给出六条可判定验收句（脱敏成立/还原成立/无感成立/商业 agent 有效/不骗人/审计红线继承），我的任务不是重复它们，而是问：每一句话**倒过来**会怎么坏？坏的时候哪个断言先红？如果答案不存在，那就是测试设计的洞。下面第一节就用这个"反着推"的方法过五条架构决策。

## 一、「测什么才算测过了」：从五条架构决策反推必钉行为

### a. 部署形态（规划 §三a）→ 第一个测试分层变量是"接入层"，不是"引擎"

决策 a 把形态定为 T1 回环显式为主 / T2 env 代理+CA 为辅 / T3 押后。这直接决定了我的测试矩阵**必须以接入层为最外层维度**：同一引擎行为（识别/脱敏/还原），在三种接法下各有一条独立的失败路径。

必钉行为：

1. **T1 壳转发保真**：method/headers/body/流式帧经壳后逐字节或语义等价到达网关；恒定 `x-anongw-session-id` 注入值跨进程重启不变（这是 b 决策的物理载体）；本地网关鉴权头注入正确且**不出壳泄漏给上游**（上游实收里不得出现本地 key——这是 1.2-#1"上游实收零原值"的一个容易漏的子项，因为 key 也是"不该出网的敏感信息"）。
2. **T2 服从性**：HTTPS_PROXY 服从、按运行时 CA 后 TLS 握手成功、CONNECT 隧道内内容可解密脱敏、QUIC 流量被识别为"不覆盖"并进披露（E1 杀死标准，规划 §四M0 E1）。注意 T2 的很多"测试"其实是 E1 的探测矩阵——我认为 E1 的输出物应该直接设计成**可重跑的适配矩阵 eval**（`t2_matrix_*`），而不是一次性实验报告，理由见 R3（agent 版本漂移需要每版本回归，规划 §5.1-R3 自己也承认了）。
3. **覆盖披露本身是断言**（1.2-#5"不骗人"）：T2/T3 形态下"哪些出口未经工具"必须是可机读的计数/清单，并且有一个负例测试钉住"绕过路径被如实报告"而不是被静默吞掉。M1 §2.2 的静默部分覆盖风险（规划 §5.1-R2 采纳为一等原则）在测试上的对应物，我认为就是这条。
4. **壳故障形态**：壳挂了流量怎么办——fail-open（放行不脱敏）还是 fail-closed（断网）？**规划没有裁决这一点**（我通篇没找到），这是开放问题清单第一条。测试设计上我只能说：无论裁决为何，"故障形态与设计一致"本身就是最高优先级断言，因为两种形态的负例测试完全相反（一个是"故障时原值不得出网"，一个是"故障时必须报错不得静默降级"）。

### b. 值级键（规划 §三b）→ 新工具的定义性断言群

决策 b 用恒定实例标识喂进 digest 的 session 槽（我重核过 `masking/mapper.py:222-224`：`msg = f"{self.session_id}...{type_value}...{normalized}"`，规划说"一行不动"是可信的——session 槽喂什么值是调用方的事）。据此钉：

1. **同值恒同**：跨请求、跨会话、跨进程、跨重启、**跨工具**（zcode 和 kimi 各自连壳，同一手机号产出同一占位符——这是"本机全局字典"的题眼，也是商业 agent 有效性的隐藏前提：模型在两个工具的上下文里看到同一种占位符语言）。第五项规划文字里有但没展开，我认为必须进断言，理由：值级键的全部价值就在跨上下文一致性，少测一项等于没测到卖点。
2. **跨实例互异**：两个安装实例（不同 instance_id/MASK_KEY）同值产出不同占位符——"换机器不可关联"（规划 §三b 引 M3 §1）。这条是新引入的隐私属性，恰好是老 m3"跨会话互异"断言的**换域复用**：断言逻辑不变，互异的域从 session 换成 instance。
3. **两形态并存不污染**（规划 §三b 明文）：显式传头的客户端走老会话语义、无头的走实例注入，同一引擎同时服务两种键域，互不串。这是我一开始想错的地方——我最初以为"值级键改造后 m3 的跨会话隔离断言怎么办"的答案是"改断言"，重读规划 §三b 后自我修正：**不是改，是分域**。基线网关形态原样保留，m3 原断言继续成立；新工具另有相反断言。测试的真正职责是钉住"域隔离"：新壳的 eval fixture 不许意外复用网关的会话头路径，反之亦然。
4. **生命周期安全失败**：TTL 过期/容量淘汰后的行为必须钉为"原样放行，不还原错人"（规划 §5.2-F5 推荐口径）。注意断言方向是"不还错"而非"必须放行"——规划留了 owner 决定空间，测试钉的是**安全不变量**（绝不张冠李戴）而不是具体策略。

### c. 判定层（规划 §三c）→ 钉"规则是裁判"而不是钉"规则很准"

决策 c 说规则为主、NER 只当识别器且 v1 不进主链。测试上我提炼出一个容易做歪的点：**v1 阶段"NER 恒空"是现状断言不是缺陷断言**——adapter `detect` 恒 `[]`（基线 §五#1）应该有一条断言钉住"影子模式开启时影子输出只进日志不进处置"，这比测 NER 准确率重要，因为它钉的是架构纪律（模型不进主链）。同理，M4 若立项，降级纪律的测试核心是**负例注入**：人为注入一个超 30ms 的慢识别器，断言主链不阻塞、回落规则、TTFT 预算仍达标（规划 §四M4 验收已列，我补一句：这个负例必须在 M4 第一天写，因为它防的是"降级开关从来没真正被触发过"——从未触发过的降级路径等于没测过）。

另外，39.8% 实体规则层不可检出（规划 §二2#4 引 M2）在测试上的正确表达是：**计数器如实报告漏检数**，而不是假装召回率能测出来。对外承诺口径（规划 §5.1-R7"按实测不按合成"）要求 holdout 报告必须分开报"合成集成绩"与"真实语料成绩"。

### d. 协议面（规划 §三d）→ 0→1 的面用"现状钉死 + 目标钉死"两端测

M1 只有 OpenAI、M2 加 Anthropic、Gemini/Responses 条件触发。测试上：

1. **现状先钉**：Anthropic 形状占位符原样直达客户端是 M2 实测的基线事实（规划 §二2#3）。我建议 t2_anthropic 的第一个用例就是"复现零还原"，作为 0 点锚——没有 0 点锚，后面"修好了"的声明就没有对照。
2. **适配器重构是回归高危区**：三薄壳（pipeline 请求遍历 / sse 组帧 / `_restore_choices`）抽接口时，OpenAI 行为不变的保障不能只靠"新 eval 过"，必须靠**老 eval 全量重跑**（M2-#5 已列 m4_routing，我认为要升级为 t0_gateway/t0_stream/t0_stream 全量）。我一度想加"响应字节级对照"，自我修正：字节级对照会把 eval 钉死在实现细节上（比如 header 顺序），语义等价对照 + 关键字节断言（占位符形态、SSE 帧结构）就够了。
3. **"请求侧检测白送"要被实测钉住**：`_aux_texts` 结构无关覆盖是 M1 单族实测的定性（规划 §二1 引），Anthropic 的 tools/system/content 数组各层叶子是否真被遍历，必须逐形状写用例，不能靠"引擎库形态无关"的定性推论。
4. **条件触发协议的测试也条件化**：矩阵里出现用该协议的 agent 才写对应 eval，不预写空壳用例——理由：空壳用例会让"测试数量"虚涨，制造已覆盖的假象，正是 1.2-#5 反对的。

### e. 性能预算（规划 §三e）→ 钉"增量"不钉"绝对值"

预算全是 TTFT **增量**口径（p50≤20ms/p95≤50ms @20KB），这是对的，因为绝对 TTFT 由上游模型支配。测试必须严格实现 A/B 双跑相减（壳链 vs 直连 mock 同进程同窗口），详见第五节。

## 二、测试分层：开发者可见 vs holdout 的边界

我的核心判据：**一个用例会诱发应试开发，当且仅当"通过该用例的最短路径"严格窄于"满足验收句的行为"**。用这个判据把规划里的测试面过一遍：

- **机械结构行为**（键语义、头注入、协议形状、转发保真）：放开发者可见。理由：通过它们没有捷径——HMAC 确定性不会因为你看过用例就改变，过拟合无从发生。
- **语料分布依赖的召回类**：必须 holdout。理由：规则和词表完全可以对着可见用例的字面调（词表演示级问题，基线 §六#9，规划 §5.1-R7 称之为"数据问题伪装成技术问题"）——如果 20 份真实文本的开发者能看见，词表就会过拟合到这 20 份的用词。
- **模型随机性依赖的对抗类**：指标口径公开、用例内容保密。理由：缓解手段（系统提示词注入文案）天然会对已知改形过拟合——E2 实测注入 6/6 vs 5/6 的增益（规划 §三g）是在 8B 模型的已知场景上量的，注入文案写过一轮后就再也不是"无先验"的了。
- **统计指标**（残留率≤2%、存活率≥95%）：指标、分母口径、杀死线全部公开；喂给指标的具体语料保密。**仪器公开、考卷保密**是我对本层边界的一句话概括。

### holdout 五个泛化面的设计（每面附"为什么它防的是那种过拟合"）

1. **真实语料分布**：与 E3 同源（owner 授权 20–50 份，规划 §四M0 E3 / §5.2-F7）。关键工程决策：holdout 库**零明文**——入库前离线脱敏，库存"脱敏后文本 + 实体位置账本"，评分时按账本重建期望占位符再对照。这条同时继承审计零明文红线（1.2-#6）并解决"holdout 库本身变成敏感文件"的问题。【本条目将来必须移出开发者可见范围：账本与原始样本】
2. **未见 agent/协议变体**：F4 种子清单（zcode/kimi/Claude Code/Cursor BYO/Cline/Aider 类）中我建议**留 1–2 个不进可见集**，专供里程碑盲测；协议变体用参数化生成器（字段改名、嵌套层级加深、多模态段混入、流式切法变化），生成器公开、随机种子保密。【种子 agent 名单与生成器种子必须移出】
3. **对抗性占位符改写库**：E2 的 18 类逼显场景（表格/markdown/代码块/JSON 参数/句中复述/截断/翻译/长上下文回指，规划 §四M0 E2）拆两层——**可见回归集**放已实测的五类改形（EN 标签/6-hex 幻觉/括号剥除/digest 重导/16-hex 扩展，规划 §二2#5 引 M1），holdout 放**生成式变体**：用 LLM 腿对占位符做"改写采样"而不是人手写规则。判据：可见集覆盖已知改形，holdout 覆盖改形空间的采样。人手写规则的对抗库一定被注入文案过拟合。【生成式改写语料与采样 prompt 必须移出】
4. **长上下文**：长度与实体密度参数公开、具体文本保密。我的判断是长上下文的应试风险偏低——O(k²) 超线性是结构性问题（规划 §二2#7，417ms@49.8k），过拟合救不了它；但"实体密度"是可过拟合参数（测试若全用低密度文本，超线性永不发作），所以 holdout 至少一组高密度夹具（3000 实体/5 万字，对齐 M3 实测条件）。【高密度夹具文本可公开，风险低——本面是我五面中唯一认为内容也可半公开的，如实记录】
5. **多轮漂移**：多轮脚本的话题转移结构公开、实体值保密。值级键下多轮一致性是结构保证（这是 b 决策的红利），但我仍要盲测一项：**跨话题同值恒同**。理由：多轮测试最容易写假——偷懒全用同一批值，看起来"恒同"其实是"只有一个值"。holdout 强制每轮换值+旧值回指。【多轮脚本实体值必须移出】

### holdout 保管与评审流程（草案）

独立目录 + 评分器与用例分离（评分器 `h1_holdout_score.py` 在仓、用例库不在）；评审节奏**按里程碑解锁**而非每 commit 跑——理由：每 commit 跑会把 holdout 事实上升为日常回归信号，开发者迟早据它调参，边界就蚀穿了；解锁时只报指标与分布图，不报逐用例明细（逐例明细会诱发对例修补）；每次解锁记录 git commit 与轮次，防"用旧数据自欺"。

## 四、对抗与安全用例的思考

### 存活率（MM2 的面）

E2 的 18 类场景三形态 15–17/18，规划 §三g 已裁"差距在噪声内，选形态是伪路"。我的测试立场因此是：**不测"哪个形态更好"，测"已知改写场景的回归 + 发生失败时的诚实性"**。结构级重组（label 与 digest 拆进表格不同单元格，M2 §3.3 判正则原理上不可救）是典型：它的测试断言不是"能还原"而是"发生时泄漏计数 +1、残留率统计如实、面板可见"——可救性测不了就测诚实性。这是本节我的核心主张：对原理上不可救的面，断言对象从"行为正确"转移到"报告诚实"，这恰是 1.2-#5"不骗人"的用武之地。

### 幻觉与补全

模型对占位符"补全"或幻觉出原值（6-hex 幻觉是 M1 实测夹具之一）有两个方向：(a) 幻觉值本身不是占位符形状，tolerant 面管不着也不该管——断言是计量面**不误报**；(b) 危险的是"占位符在、旁边躺着模型编的像原值的东西"，用户无从分辨真伪。方向 (b) 我判断 v1 无断言可写，只能进披露面（残留计数 + 面板），如实登记为测试覆盖不了、只能靠 UI 呈现的面——写成开放问题而不是假装有测试。

### 渗漏可见性（MM1 的面）怎么变成断言

三层递进：第一层**仪器校准**——M0 两个补丁（标签副索引、裸 digest 检测面，规划 §三g）的验收就是"已知泄漏样本 100% 命中 + 正常文本含 hex 字样零误报"，补丁没过校准之前，一切残留率数字都是坏仪器量出来的（规划 §三g 自己说了"计量仪器校准"这一定位，我完全同意并认为它是全部安全测试的第一块多米诺）；第二层**运行时策略接线**——`tolerant_placeholder_hits`（我重核在 `mapper.py:177`）接计数器后有"计数≥1 时托盘可见"断言；第三层**端到端负例**——每个协议/agent 组合跑一次"必泄漏夹具"（EN 标签翻译形态），断言它最终被计量捕获而非静默穿透。

### 上游实收零原值

bytes 级扫描断言（基线 §三表 B"三族冒烟实测"）从冒烟级升格为**每协议必跑**：OpenAI/Anthropic 各自的请求侧全部字符串叶扫描零原值，含 tools 定义、system、历史消息。另补一个易漏子项：本地网关 key 也不得出现在上游实收（第一节 a-1 已述）。

## 五、性能与无感在 CI 里怎么不抖（GLM2 四实验之一的落地思考）

四个证据定调：基线 §三表 B 注明"全部毫秒值为单机单窗口实测……只作通过佐证不作稳定指标（交叉MM C20/D11）"；基线 §七#3 门禁失败点随轮次漂移；基线 §六#16 :9004 隧道是单点；m3 现行 perf 用 `time.perf_counter()` 多次均值（`evals/m3_masking.py:615-620`）。结论：**预算测试天然抖，抖的主要来源是上游与机器，不是被测代码**。我的设计四条：

1. **测增量不测绝对值**：同一进程内 A/B 双跑（壳+网关开 vs 直连 mock 上游），同时钟域相减。上游模型的数百 ms TTFT（规划 §三e 表）在差分里对消，剩下的才是工具自身的责任面。
2. **统计纪律**：样本量下限（我建议 ≥200 请求，与 E2 的 200 轮对齐省一套夹具）、预热丢弃首 N 次（连接建立/字节码缓存）、每次输出完整分布而非单值——p95 对 200 样本就是第 190 序列值，样本少时一个离群点就是一次假红。
3. **双轨门**：CI 宽门（预算 ×2，防机器波动误杀，红即报警不阻塞）+ 里程碑窄门（受控窗口人工复测，按规划预算严格判）。写进 thresholds 注释。理由直接引基线教训：门禁对环境敏感是已被三族复现的事实（§七#3），单轨门要么天天假红要么被迫放宽到失去意义。
4. **CI 只用 mock 腿**：TTFT 增量在 mock 上游下测（确定性时延可注入）；:9004 真实腿只做里程碑抽样。与第 3 条共同构成"CI 不抖"的根。

无感的行为面（非性能）单独列：流式候选缓冲不放大首 token 延迟、`≤48 字符候选缓冲 + 命中即冲刷`语义保持（规划 §三e 表）、agent 任务完成率（M2 矩阵的端到端判据）。最后这项提醒我：**"无感"的终极测试是"agent 的活还能干成"**——20 轮真实使用的验收（规划 §四M1-#2）本质是一次可用性回归，不宜降格为纯性能数字。

## 六、目录结构、命名与优先级

```
anongw-transparent/
  evals/
    thresholds.py            # 独立阈值表；预算常量必须有消费它的 eval（附 lint 自查）
    t1_shell.py              # 壳单测：头注入/转发保真/流式中继/故障形态（按 fail-open/closed 裁决定）
    t1_roundtrip.py          # 值级恒同×5 面 + 归一化等价还原 + 泄漏计数 0 + 两形态域隔离
    t1_leak_calibration.py   # 检测面仪器校准（M0 两补丁的验收本体）
    t2_anthropic.py          # 0 点锚（复现零还原）+ 形状还原 + event-stream 组帧
    t2_largecontext.py       # 50k 高密度夹具性能
    t2_matrix_<agent>.py     # 逐 agent 一文件（真实 agent 用例独立成文件，便于按版本重跑）
    h1_holdout_score.py      # holdout 评分器（评分器在仓，用例库不在）
  holdout/                   # 独立保管，内容按第二节标注逐步移出开发者可见范围
  fixtures/adversarial/      # 可见对抗回归集（E2 18 类 + M1 五改形）
```

命名延续基线 m/t 前缀、新增 h 前缀（holdout）。理由：`evals.<模块>` 直跑 + exit 0 是三族验证过的惯例（基线 §八#2），延续的认知成本最低；h 前缀制造物理隔离，让"哪些文件永远不该给开发者看"有目录级答案。

**优先级**（按"杀死错误路线最早"排序，即 M0 精神，规划 §四M0）：

1. `t1_leak_calibration`——仪器先于测量。M0 步骤 1 的验收就是它，其他一切残留率数字以它为前提。
2. `t1_roundtrip` 的值级恒同子集——新工具的定义性断言，M1 竖切第一天就要红/绿。
3. E2 存活率回归矩阵——M0 天花板实验，决定占位符机制生死（<95% 杀死线，规划 §1.2-#2）。
4. TTFT 增量双轨口径——E4 骨架先跑通口径再进 CI，别让预算测试反过来绑架架构（h 接法的进程内收敛就等它的数据，规划 §三h）。
5. `t2_anthropic`——M2 的 0→1 面，0 点锚先写。
6. holdout 评分器与用例库——与 2–5 并行构建，按里程碑解锁。

## 七、开放问题登记（不装懂）

1. **壳故障形态未裁决**（第一节 a-4）：fail-open vs fail-closed，规划全文未明说，但它是负例测试的设计分叉点，建议进入 owner 分叉清单（F9 候补）。
2. **非目标协议到达 T1 壳的行为未定义**：透传？501？按 §三f 的"绝不静默"精神我猜应显式拒绝，但这是猜测，不是裁决。
3. **残留率 ≤2% 的分母口径**："按占位符计"在流式同响应重复出现、跨响应重复出现时怎么计，需在测试文档定案前补口径。
4. **holdout 的对抗面采样依赖商业模型腿**，而 E2 已自注 8B 数字不外推商业模型（规划 §四M0 E2）——商业模型在 CI 的可用性与成本未定，holdout 对抗库的更新频率由此受限。
5. **性能预算的机器基线**：预算是按 windev-01 实测定的（规划 §三e 表依据列），换机器后双轨门的宽倍率（×2）是否还合适，需要一次跨机器标定。
6. 我没有运行任何基线 eval（本任务红线是只读+写本文件，且跑 eval 会起端口服务），第一节以下所有"现状"均引规划/基线或我的只读 grep/sed，无一处是我实跑 eval 得出的——如实声明。
