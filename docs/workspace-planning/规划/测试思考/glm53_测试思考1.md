## 一、"测什么才算测过了"——从 a–e 决策反推

**总判据：这个工具的"测过了"是三层证据的合取，不是 eval 全绿。**
1. **契约层**：规划 §1.2 六条可判定验收句各有对应断言（脱敏/还原/无感/商业 agent 有效/不骗人/审计红线继承）；
2. **泛化层**：在开发者没见过的语料、agent、改形上指标不塌方（见第二节）；
3. **诚实层**：计量仪器被校准、覆盖边界如实披露——"不骗人"在 §1.2-#5 是一等原则，它本身就是可测对象。

只做到 1，就会重演规划 §三c 引 M3 那句话的局面：「评测完美、生产撒谎」。

### a 部署形态（§三a）→ 必钉行为
- T1 回环壳：**只听回环**（负例：非回环接口不可达——R10"工具自身成为攻击面"的测试化）；**转发保真**（除注入头外请求体逐字节不变，响应除应做的还原外逐字节回来）；**流式中继不丢帧不改序**。
- T2 wrapper：**只染子进程 env**（父进程与系统环境不受染，负例）；**不写系统信任库**（对系统证书存储扫描的负例——§三a 硬承诺）；**pinning 命中→排除名单**。断言方向必须是想清楚的：测"如实披露存在"，绝不是测"绕过成功"——§1.3 明确不做绕过，把红线写成验收是测试设计的自我背叛。
- 透传形态（§三f）："绝不静默"的可判定化 = 两个负控断言：密级命中时客户端收到**可判别信号**（形态正确的代答体或 403）＝不静默拦截；mock 上游**零触达**＝不静默放行（直接继承基线 §2.3 "BLOCK 恒 null upstream"口径）。
- **"不骗人"的测试化**：构造一个已知未覆盖的出口（如 pinning app），断言矩阵/面板把它登记为"未覆盖"。普通工具不需要测自己的诚实，这个工具需要。

### b 值级键（§三b）→ 必钉行为
- 同值恒同**四档**：跨轮、跨会话（无会话头）、跨进程、跨重启（前两档功能断言，后两档是 M3 持久化验收）。
- 异值恒异；**类型不同恒异**——实读确认 type 在 HMAC 消息里（mapper.py:222-224），此性质第四节还要用。
- **两形态并存不污染**（§三b 原文）：基线网关会话级语义原样成立，壳注入的实例级语义照常工作。
- **"mapper 公式零改动"如何钉**：金样本比对——固定 MASK_KEY+instance+type+normalized，跨版本断言 digest 不变。b 裁决把"一行不动"当设计承诺，测试就该钉承诺。

**一个重要推论（自我修正①）**：我最初以为 m3 要改造出"值级断言版"。细读 §三b 后修正：值级语义的实现位置在**壳层恒定注入会话头**，mapper 零改动——所以值级断言全部落在新 eval（壳-网关集成层），m3 原样保留，但从"新工具的验收"降格为"引擎不被顺手改坏的回归网"。**m3 通过对新语义是必要非充分**——这个"非充分"不在新 eval 里补上，就会出现"16 模块全绿但值级语义根本没实现"的假阳性。

### c 判定层（§三c）→ 必钉行为
- v1 主链零模型依赖：主链在语义 judge 降级态照常工作（基线 §五#3：现状本就是降级面）。
- **召回报告分层**：结构化召回（1.0000/618，基线 §2.1）与开放词表缺口（39.8% 规则层不可检出，规划 §2.2#4）是两个数字，eval 输出 schema 应拆成两个字段——把 R7（"演示级词表伪装成数据问题"）的防御做进报告格式，防止合成集 micro 召回对外代言全局。
- M4 门槛（影子净胜/30ms 降级/span 仲裁/白名单 0/22 复刻）v1 只留占位；但 span 仲裁夹具可现在就写——`mask` 按 start 降序逐个切片（mapper.py:262 实读），两层重叠 span 拼接会坏，这是已知雷，夹具先行成本极低。

### d 协议面（§三d）→ 必钉行为
- **适配器重构的安全网**：三薄壳抽接口（§四 M2）是最大重构，OpenAI 行为须字节级不变。实读确认 `_restore_choices` 只认 `choices[*].message.content` 与 tool 参数（pipeline.py:828 起）、`format_sse` 只产 `data:` 行（sse.py:56-61）。重构前后对**录制的上游响应语料**做 A/B 双跑字节比对——比"重跑 t0_stream"更硬：行为断言会放过实现内部变化，字节比对不会。
- **请求侧结构无关检测**：`_aux_texts` 遍历顶层键+递归字符串叶（pipeline.py:195/172）。基线 §八#3 待复核项 (1)（JSON 键检测面两族判已修 vs SR 判未覆盖）正是争议点——**测试应先把这条钉死**：构造"键名含敏感值/键名换名/深嵌套"夹具断言期望行为，跑出的事实就是销项证据。这是测试替基线销项的直接例子。
- **候选缺口（待定级）**：`_iter_string_leaves` 只产字符串叶——agent 把手机号/身份证作为 **JSON number** 字面量发出时检测面原则上看不见。先写成登记缺口的夹具交 owner，见第七节问题 2。
- **Anthropic 事件流**：夹具=构造/录制的 event-stream，占位符落 `content_block_delta`/`input_json_delta` 内，且**逐字节重切 chunk 边界**（fuzz——复制基线 t0_stream 的 500 组切块方法论，基线 §2.2）。
- 条件协议（Gemini/Responses）：预写夹具格式与测试骨架，矩阵出现需求即启用（§三d 触发条件），不出现不实现。

### e 性能预算（§三e）→ 钉定义，测法见第五节
预算句最易含糊的是"增量"的**归因**：TTFT 绝对值由模型与网络支配，工具只对"经工具 vs 直连同上游"的差值负责。测量定义必须先进测试设计、后进代码，否则 E4 与 M1-#4/M2-#3 的数字不可比。

## 二、测试分层：开发者可见 vs holdout

**核心判据：一条用例的字面内容被开发者看见后，是否存在"针对字面优化而损害泛化"的激励。有→holdout；无→可见。**
- 断言**契约**的用例（同值恒同、密级零触达、401、头注入）没有应试激励——行为要么成立要么不成立，无可背之处，全部可见。
- 度量**能力/分布**的用例（真实语料召回、改形存活率、未见 agent 打通率）有应试激励——词表会往用例上调、注入提示词会往改形清单上调，必须分区。

五类泛化面：
1. **真实语料分布** ▌holdout：E3 的 20–50 份授权政务文本、真实 agent 转录。可见则词表/启发式必然向其过拟合（R7 的机制）。机制：可见评测集与 holdout 同测量代码双跑，**两数字之差本身就是过拟合度量**，进阶段报告。
2. **未见 agent/协议变体** ▌holdout（部分）：种子矩阵（F4：zcode/kimi/Claude Code/Cursor BYO/Cline/Aider 类）可公开——接入方式不是秘密；但 M5 应另跑 ≥1 个**不在开发清单的** OpenAI 兼容 CLI 作泛化探针，身份与结果只在阶段门披露。
3. **对抗性占位符改写** ▌holdout（一部分）：E2 改形语法表（表格/markdown/代码块/JSON 参数/翻译/截断…，§四 E2）可公开——两个 M0 补丁的靶向类就来自它（标签副索引靶向 EN 翻译、裸 digest 面靶向括号剥除，§三g）；但**改形语法的组合变异**（LLM 批量生成新改形）必须 holdout——注入增益本就薄（有注入 6/6 vs 无注入 5/6，§三g），经不起对着考卷调。
4. **长上下文**：夹具模板可见；**实体密度/位置分布参数** ▌holdout——位置召回衰减可被"对固定位置调提示"吃掉。
5. **多轮漂移**：小规模可见（开发须能复现），长程/模糊变体 ▌holdout。

**操作机制**（与 m7 审计纪律同构——测试工件也不该泄漏考核内容）：holdout 内容**不入仓**（仓库只放 runner+manifest 哈希，内容由 owner 阶段门运行时注入）；只在 M2/M5 阶段门跑、不进每次提交的 CI（防高频运行变调参信号）；报告只出**计数与比率**不出原文——日志与报告自身过一遍"原值扫描"。

## 四、对抗与安全用例

**1. 结构级重组（存活率问题）**：模型把 label 与 digest 拆进表格不同单元格——canonical_placeholder 要求恰两段（mapper.py:124 实读），拆开后正则原理上救不回（规划 §2.2#6 已承认为残余）。测试的义务不是"修复"而是：逐改形类型**分列**存活率（不能只报均值——两补丁各有靶向类，聚合数会掩盖补丁是否真命中靶向）；断言计量器对不可救类正确计数；断言残留率按 §1.2-#2 口径披露。**测"诚实的失败"是这个工具的特色测试**。
**2. 幻觉/补全占位符**：方向分析——幻觉 digest（6-hex/16-hex 扩展）查表必不命中→原样放行入泄漏计数，无错还原。**错还原**要求 lookup 命中错值：值级键下同 digest 必同值（插入期碰撞升位，基线 §2.2）、type 掺在 HMAC 消息里（mapper.py:222-224 实读），所以"模型把手机号换标成 ID_CARD"得到的是查表未命中而非错值。由此提出**独立于残留率的安全断言：错还原率=0（宁残留、不错还）**——残留 ≤2% 是质量线（失败→披露），错还=0 是安全线（失败→一票否决），分开断言分开处置。夹具：换标签/补零扩展/伪 hex 各若干。
**3. 渗漏可见性断言化**：五改形夹具逐条（EN 标签翻译/6-hex 幻觉/括号剥除/digest 重导/16-hex 扩展，规划 §2.2#5 引 M1 实测）；两补丁各配**红/绿演示**夹具（补丁前 FAIL、补丁后 PASS）——钉住"已坏输出判 PASS"盲区确实被修（修补前 U8 断言仍 PASS 正是仪器坏的证据，§2.2#5）；**检测面自身的误报负例集**：tolerant_placeholder_hits 设计上偏宽（mapper.py:177-200 docstring 自认"比 RESTORE_PATTERN 宽"），今天没有负例集——仪器校准必须含仪器误报率，否则"泄漏计数"这个一号运行时指标（§三g）本身不可信；计数入审计且零明文（m7 口径）、面板数=审计数。
**4. 请求侧对抗**：检测面外位置逐个定级——JSON number 叶（候选缺口）、深嵌套字符串（递归遍历应可覆盖，写夹具证实）、键名（待复核项 (1)，钉死）、base64 编码值（登记不做、诚实披露）。

## 五、性能与无感在 CI 里怎么测才不抖

E4（规划 §四 M0）的 harness 就是 M1-#4/M2-#3/M5 终验的同一把尺，须一次做对。五条设计：
1. **测差分不测绝对**：工具归因增量 = 经工具 TTFB − 直连**同一 mock 上游** TTFB；mock 消掉网络与模型方差。绝对 TTFT 测的是别人的性能。
2. **交错 A/B 配对采样**：直连/经工具逐对交替（同负载、同体量、同连接状态），取逐对差值再算分位——机器漂移对两腿同向作用，差分后抵消。这是防抖核心。基线 §三表 B 注已明告"全部毫秒值单机单次、不作稳定指标"：单次绝对数永远不进判定。
3. **样本量与预热**：p95 没有几百样本无意义；预热丢弃；请求体种子化固定（复用 m8_generator 思路）。
4. **双门设计**：功能 CI 门放宽到 **2× 预算**（p95≤100ms@20KB）防粗大回归，边缘失败三次复跑；精确预算（p95≤50ms）只进**独立性能道**（定时/阶段门），并带环境失真检测——直连基线自身超出历史波动带即判"环境无效"，不 fail 构建。
5. **流式无感的可测代理**："无感"不可直测，测三个代理：块级增量延迟分布；**输出滞后上界**（输出前缀落后上游到达 ≤48+ε 字符，即候选缓冲语义不被放大，基线 §2.2）；M3 的 ≥10 路长流并发零交叉污染（m11 哨兵模式）。

大上下文（M2-#3：p95≤100ms@50k）：不只测终点，做 **5k/10k/20k/50k 密度扫描**看拐点——O(k²) 在 20k 段就会露头（M2 曾实测 20k 近线性、超线性高密度才咬人，规划 §2.2#7），只测 50k 会放过中期回归。
